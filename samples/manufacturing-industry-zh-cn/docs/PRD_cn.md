# PRD：制造业端到端计划与履约样例

## 业务背景

离散制造企业的订单、物料、工单、执行、质量和维护事实通常分散在 ERP、MES、QMS 和设备系统中。业务团队能分别查询记录，却难以形成一条可复核的结论：某张客户订单对应的工单是否在受控条件下完成，质量是否支持放行，阻塞点在哪。

本产品提供从需求预测到生产计划、物料发放、执行、质量、成品入库和发运的可复核事实追溯，不替代 ERP、MES 或 QMS 的交易处理。

## 业务方与核心关切

| 业务方 | 业务关切 | 希望获得的结果 |
|---|---|---|
| 订单履约负责人 | 客户需求是否已形成可执行计划并具备发运条件 | 不必人工拼接系统，就能得到有证据的履约状态 |
| 生产主管 | 已完成步骤是否由合格设备和人员在正确现场条件下执行 | 发现状态已完成但执行不合规的记录 |
| 质量负责人 | 最终检验是否支持放行 | 将检验状态、规格结果和具体工单关联起来 |
| 物料主管 | 已发放物料是否覆盖工单需求 | 明确覆盖率、未覆盖数量和对完成判断的影响 |
| 数据/本体负责人 | 跨系统概念与结论是否可解释、可复用 | 统一的业务对象、关系和来源语义 |

## 核心业务决策

### D1：工单是否可以履约

履约判断必须同时满足计划已下达、BOM 版本已冻结、物料覆盖、全部工艺步骤已完成且执行合规、最终质量符合、成品已入库和发运条件成立。任何一项不满足时，必须说明阻塞事实。

### D2：已完成执行是否可信

每条完成执行都应核验设备能力、人员资质、工作中心和已安排的班次日期。业务方需要得到逐项通过、失败或未知的原因。

### D3：最终质量是否支持放行及发运

最终检验批必须已接受，且每项测量结果都在规格上下限内；完成发运还必须关联该工单的已接受成品入库，且发运数量不得超过订单和入库数量。缺少检验、测量或入库时结论为未决。

### D4：物料是否阻塞工单

业务方需比较需求量和已发放量，并能从收货和库位追溯发放事实。

## 样例业务范围

场景由三个相互关联的业务域组成：

- **主数据：**基地、工作中心、产品、BOM、工艺路线、设备、能力、人员和班次。
- **需求与供应：**客户、销售订单、预测、生产计划、供应商、采购、收货、库存地点、物料发放、成品入库和发运。
- **生产运营：**工单、物料需求、工序、步骤、人员安排、执行记录、质量规格与检验、维护。

样例计划时间跨度为 2026 年 11 月至 2027 年 3 月，业务时间事实均采用日期粒度。2026-10-20 的计划快照与 2027-03-31 的实际库存快照明确分开，避免把事后运营结果误当作计划时点的已知事实。

## P0 业务场景与验收

| 场景 | 用户故事 | 业务验收结果 |
|---|---|---|
| 订单到工单追溯 | 作为履约负责人，我要从销售订单找到工单、产品、BOM 和工艺路线。 | 返回完整关联链和稳定业务标识。 |
| 工单完成判断 | 作为生产主管，我要知道工单是否满足物料、执行、质量门。 | 返回完成、未完成或阻塞，以及每项证据。 |
| 执行条件核验 | 作为生产主管，我要核验设备、人员、工作中心和班次。 | 每条执行返回通过/失败/未知及原因。 |
| 最终质量判断 | 作为质量负责人，我要确认最终检验能否支持放行。 | 已接受且全部测量在限值内才返回通过。 |
| 物料覆盖判断 | 作为物料主管，我要识别物料不足是否阻塞工单。 | 返回覆盖率和未覆盖数量。 |

P1 包括异常事实链解释和中英文一致的业务结论。

## 成功标准

1. 业务人员可从预测追溯到计划、订单、发料、执行、最终质量、成品入库和发运，不需手工拼接多个系统。
2. 每个完成、未完成或阻塞结论都可用业务记录复核。
3. “已完成”状态不能掩盖设备、人员、工作中心或班次不合规。
4. 质量放行必须同时依赖检验接受状态和可复用质量规格结果；发运必须关联合格成品入库。
5. 同一业务问题在中英文版本中获得相同事实结论。

## 边界

样例回答需求支撑的工单是否已有计划供给、足额发料、合规执行、合格最终质量、成品入库和可发运结论。不做最优排程、ATP、批次谱系或根因处置；这些能力仍需要有限产能、客户分配规则、批次/序列号谱系和不合格处置流程。

事实不足时必须返回未知、未决或阻塞，并指出缺少的信息；不得用建议、概率或推测替代事实。

## 非目标

- 不替代订单、采购、仓储、MES、QMS 或 EAM 的交易流程。
- 不生成派工、采购、维护或客户承诺建议。
- 不将工单完成表述为订单交付完成。
- 不将 IOF 覆盖实例表述为企业真实运营记录。

## 与方案设计的关系

本 PRD 只定义业务需求和验收结果。数据模型、IOF 映射、指标、函数、Skill、题库和安装方式是对这些需求的方案响应，必须证明满足 P0 场景，不能以技术可实现性扩大业务范围。
