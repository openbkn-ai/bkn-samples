# Retail operational rules (public calculation contract)

All quantities are Decimal strings in product base unit `ea` (中文display `件`); movement unit `case`/`箱` multiplies product.pack_multiplier. Standard IDs synthetic. All dates inclusive. as_of_date and knowledge_date are required; source known_date/recorded_date must be <= knowledge_date. Actual event_date must <=as_of_date and view_code=actual, planned facts never count in inventory. Function results keep status_code and issue code in English; localized display state stored separately.

## Tables and events

movements.movement_id is physical source row PK, event_id is semantic event identity; duplicate event_id with identical business payload counts once (ignore movement_id/recorded_date in payload comparison), conflicting visible payload invalidates only the source/destination lot/location balances touched by either conflicting version (null values, not zero). Independently known warehouse stock remains known when a store sale conflicts. event_type_code = receive, dispatch, arrive, sale, return, consume, produce, adjust, reversal. receive/produce credits destination, sale/consume debits source, return credits destination and is quarantined; adjust credits destination signed quantity. dispatch debits source and adds transfer_id in-transit at destination; arrive credits destination and subtracts in-transit for same transfer. Reversal row carries reversal_of=event_id, quantity0; once visible cancels target and its effects. No sequence tie allowed for different event IDs on same lot/date/event_sequence.

Inspections: latest (inspection_date,inspection_id) visible per lot at <=as_of_date determines passed/failed/pending. Missing inspection is pending and blocks sale; latest failed/pending quarantines all on-hand. Inspections apply lot-wide, location is where test occurred. Holds active on effective_from<=asof<=effective_to with known_date<=knowledge cutoff; rows represent disjoint claims except explicitly stated return overlap. holds.return_overlap_quantity states how much of that hold overlaps returned units; it must not exceed hold quantity, and total overlap must not exceed returned quantity. Physical quarantined=min(nonnegative onhand,max(total_returned+sum(active hold quantity)-sum(return_overlap_quantity), onhand if inspection not passed else0)). Return is always quarantined; explicit overlap is not deducted twice. Null/negative stock, missing dispatch before arrival, over-arrival, conflicting event, invalid overlap, returned quantity exceeding sales, missing lot master or same-day sequence tie produces issues; affected on_hand/available are null when a numerical balance cannot be trusted. Returned units are never re-dispatched in this dataset; release/reclassification of return cohorts is outside the sample's action scope.

Reservations active by dates/knowledge. They reference order_lines; cap at stock remaining after physical quarantine, expiry and active recall block. available=onhand-quarantined-recall_blocked-reserved; expired stock has available0. Inventory rows fields: product_id, lot_id, location_id, unit, expiry_date, inspection_status_code, on_hand, in_transit, quarantined, recall_blocked, reserved, available, sold, returned, expired, near_expiry, quality_status. near_expiry means 0<=expiry-asof<=14 days. expired means expiry<asof. One row per observed lot/location, including source with0 and intransit-only destination. Unit is base unit, all Decimal output qty strings use six decimals (ratios six decimals).

Lot link closure is directed parent->child. Visible if effective_date<=asof, known_date<=knowledge. `split` equal product/unit quantities conserve within stated link; `transform` may change product and is trace connectivity only. Cycle yields incomplete recall. Active recall announced<=asof and known<=knowledge, status_code=open, blocks unquarantined affected stock. Batch descendants inherit recall block regardless different product.

## Function scope

execute(operation,tables,contract,scope). inventory_asof and fulfillment_plan require product_ids array1..50; optional location_ids and lot_ids narrow outputs but source validation must retain complete relevant paths. as_of_date, knowledge_date; view_kind actual/planned. inventory always actual stock, view_kind only labels intent; forecasting only in fulfillment. recall_assessment requires recall_id and ignores optional product_ids when constructing full descendant set. Each output includes scope/rows/issues/evidence/completeness (complete|partial), integer schema_version1/capability. None means unknown.

inventory_asof supports trace_lot_id optional, returning trace_rows list with parent_lot_id/child_lot_id/link_id/link_type_code for visible connected upstream+downstream links (traverse BOTH directions). Inventory rows remain product/location filtered; trace is independently complete for connected component. quality_status=known|unknown.

## Allocation and planning

fulfillment_plan mode=orders(default) or replenishment. Orders visible order_date<=asof/known<=cutoff, status_code=open; optional order_ids restrict demand, NOT existing reservations. Overdue open orders remain included. Sort priority ascending then due_date/order_id/line_id. Allocate from order.location_id and line.product_id, passed inspection, expiry_date>=max(asof,due_date)+line.min_shelf_days; FEFO expiry/lot. No substitutions. Preserve reservations for other lines, restore own reservation before assigning its line, release unused own reserved quantity after its line. Capped usable reservations are assigned once in reservation_id order; never restore the same capped quantity to multiple lines. Shared stock decrements once across orders. If line_id is excluded its reservation remains unavailable. rows one per line with line_id/order_id/product_id/location_id/unit/requested_quantity/allocated_quantity/shortage_quantity, allocation_status_code full|partial|shortage|unknown, allocations list {lot_id,quantity}. shortage0 is meaningful, unknown quantities remain null.

Replenishment: horizon_date default2027-03-31 >=asof. forecast view_code=planned, known_date<=cutoff, asof<demand_date<=horizon; scope product/location. Only receive/produce planned events known by cutoff whose destination/location/product match and date<=demand_date, lot has latest passed known inspection and expiry>=demand_date+product.min_shelf_days; active recall blocks them. Start from current AVAILABLE inventory (subtract reservations, physical quarantine/recall/expiry); track lot buckets and expiry as days advance, process planned supply before day's demand, FEFO consume forecast. Output one row per forecast: forecast_id/product_id/location_id/demand_date/unit/demand_quantity/eligible_supply_quantity/allocated_quantity/shortage_quantity/recommended_quantity. eligible_supply_quantity is balance after that day's inflows/expiry, before consumption; recommendation=shortage (read-only no MOQ assumed). Missing balances make scope uncertain, cannot recommend a fabricated number.

## Recall

recall_assessment rows one per affected product/location, grouped separately by product and base unit (never aggregate product quantities). Fields recall_id/product_id/location_id/unit/affected_lot_ids, on_hand, in_transit, sold, returned, controlled_quantity=physical quarantine, pending_control_quantity=onhand+intransit-controlled, controllable_quantity=onhand+intransit, coverage_ratio=controlled/controllable rounded half up6dp iff denominator>0 and complete. Sold is cumulative outbound sale less return; returned separately counted but included in on_hand and controlled, never added a second time to denominator. If returns exceed sales, report issue and null rather than silently0. Includes affected_order_ids: non-reversed sale events' order_id at this group location and affected lot, plus visible open order IDs with active reservations against affected lots at this same location. Dispatch/return/consume order references do not imply a fulfilled sale. A missing flow/invalid source yields null coverage/unknown counters, completeness partial, evidence and issues retained. Existing stock holds and return blocks count as physical control even if hold reason predates recall. Zero denominator => ratio null, not100%. Root unavailable/unannounced/closed => no rows + explicit issue.

inventory_snapshots and recall_snapshots are recorded snapshots for 2027-02-28 that match recomputation for the same as-of and knowledge dates; read them with Cypher for that day, and call the functions for any other date or detail they do not hold.
