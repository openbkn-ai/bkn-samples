# 食品供应链运营：批次追溯、库存履约与召回 PRD

状态：开发基线；尚未完成安装及问答验收。交付两个独立可安装样例 `retail-gs1-en-us`、`retail-gs1-zh-cn`，业务事实和标识一一对应，展示名称、业务值、问题与答案按语言表达。保留已有采购/BOM供应链样例，本样例补充食品流通和召回业务。

## 业务目标与使用者

质量负责人发现供应商批次有质量问题时，需要准确回答“哪些货受影响、在哪里、多少可隔离、多少已售、哪些订单要停止出库”；仓配负责人需要在隔离和效期约束下安排履约、调拨与补货；门店负责人需要了解可售库存及即将到期风险。每个结论须给出业务日期、知识截止日、数量单位、依据记录及不确定性。

成功标准是从来源事实重建批次流向、可用库存和召回处置建议，并使业务问题、能力与验收题相互对应。只给查询对象和孤立表格不足以满足此需求。

## 决策范围

纳入：供货、到货质检、入库、仓店调拨、在途、销售、退货、隔离与释放、效期、订单预留、履约缺口、已知需求预测、补货建议、批次转换关联、召回范围及处置覆盖。

不纳入：真实采购/支付/出库执行、运输路线优化、机器学习预测训练、自动召回通知、法规合规认证、财务结算。建议只读，不能承诺实际执行。预测是明确标注的虚构业务输入，不包装成模型预测精度。

## 业务时间与数量契约

1. 数据覆盖 2026-11-01 至 2027-03-31，默认观察日 2027-02-28。每次分析指定业务日期、知识截止日期与实际/计划视图。未来需求与在途到货用于规划，不能计入已发生库存。
2. 用户展示到日期。为保留 EPCIS 语义，原始事件允许带时区时间；业务日期及事件顺序另有明确字段。同日顺序使用稳定序号，不能靠 ID 字典序猜测。记录日期用于迟报可见性。
3. 同一事件 ID 的重复导入不重复计数；撤销事件在其可知日后取消对应事件影响。冲突副本、缺失必需流转、负库存均作为质量问题暴露，不能静默归零。
4. 数量以商品基准单位计数；包装换算只能使用已声明倍率。不能相加不同单位来生成业务总量。调拨出库与到货各记一端，在途单独计算；销售离开可控库存，退货进入隔离区。
5. 可用量 = 已接收且未离开的在库量 − 有效隔离量 − 有效预留量，要求不重复扣减同一货量。到期日当天可售仅限满足订单剩余保质期规则；已过期不可售。已预留订单履约时不能再次扣减其自身预留。
6. FEFO 按到期日、批次 ID 稳定排序；先匹配地点、商品、订单截至日、剩余保质期与质量状态，再分配。订单共享可用库存，不能每单独立使用同一份货。相同优先级按交期、订单ID排序。可见未关闭的逾期订单属于待履约积压，不能因为交期早于观察日而被漏掉；其效期门槛以观察日和交期的较晚者计算。
7. 召回包含受影响原料/供应商批次经声明转换产生的下游批次，保留直接与间接证据。跨产品转换不把原料件数与产成品件数直接勾稽；只有声明同单位且守恒的拆分才做数量守恒。
8. 已隔离与待隔离分开；已售与已退回分开；未知流向单列。召回处置覆盖率分母为同商品/基准单位的受影响在库量+在途量，不含未退回的已售量；分子为该在库量中已证实控制的部分。退货已进入在库，不能再次累加；在途未经到货或明确控制证据不能计入已控制。分母为零或覆盖不完整时比例为 null，未知不是0。质量/退货阻断与有效隔离按并集扣减，不能重复扣同一批货；隔离来源显式记录与退货覆盖的重叠量，不能默认所有隔离相互重叠或彼此独立。预留只扣剩余合格可用部分，超额预留须报告问题。

## 业务场景与验收分配

每语言固定100题，基础30、中等40、复杂30。以下ID属于业务需求，题目引用同一场景ID，答案引用证据ID。需求覆盖和难度在 PRD 中维护，不新增重复的“场景需求”文件。

|---|---|---|---|---|
| S01 商品、组织、地点 | 商品单位、包装和供应商责任是否清楚 | 主数据、倍率、关联角色与缺失提示 | Q001–010 | 6/3/1 |
| S02 到货与质检 | 本批到货能否入可用库存 | 接收量、质检结果、隔离/可用数量与来源 | Q011–020 | 4/4/2 |
| S03 批次流向 | 货从哪里来，经哪些流转到哪里 | 含转换的上游/下游路径与影响集合 | Q021–030 | 3/4/3 |
| S04 库存与在途 | 仓店真实可售库存是多少 | 在库、在途、隔离、预留、可用及异常 | Q031–040 | 3/4/3 |
| S05 效期与滞销 | 哪些货应优先发、停止发或补货 | 近效期清单、可履约限制与FEFO证据 | Q041–050 | 3/4/3 |

## 最小能力设计

保留三个函数，一个业务Skill，两个指标，避免为每道题建函数。

- `inventory_asof`：实际事件重建、在途/质量/隔离/预留/效期拆分、来源证据、数据质量问题；同时提供上下游批次追踪。覆盖S02–S05、S10。
- `fulfillment_plan`：订单共享库存FEFO分配及到2027-03-31的需求/合格供给缺口建议；处理质量与召回限制，结果为建议。覆盖S06–S07、S09。
- `recall_assessment`：沿批次转换关系计算影响范围、按地点和状态分解以及控制缺口。覆盖S03、S08–S10。
- 指标：带日期、商品、地点、单位的“可用库存量”；指定召回的“处置覆盖率”。必须注册并真实查询；若依赖记录快照，明确快照性质和与函数重算的核对方式。
- Skill：供应链异常调查。先确定范围和截止日，再选择上述能力，核查 issues/完整性，给出证据支持的原因及只读建议。不塞入题号、测试答案或特定记录结论。

函数只包含通用规则，不能接收题号、读取题库或返回预制答案。函数输出结构固定：scope、rows、issues、evidence、completeness；数量精度和未知值策略明示。主数据简单查值仍使用对象查询。

## 本体与标准边界

使用 Apache-2.0 的 GS1 Web Vocabulary 作为可复用语义来源；EPCIS/CBV用于事件和业务步骤参考，逐项核验再分发许可。按BKN当前规范建立对象、属性、关系和概念分组文档，记录具体source IRI、定义、版本/提交及许可证；采购/预留/预测/召回处置属于明确的本地运营扩展，不声称GS1全量等价或实现完整EPCIS服务器。

范围完整性以本PRD业务闭环为准，不以导入标准所有词条为目标；不创建没有数据或业务用途的空壳类。每个已声明对象均有可关联样例，常规主数据表至少50行，业务事实表按场景需要提供明显更大且有差异的数据；不能用“批次001”后缀冒充不同供应商或商品。

## 数据与双语要求

全部虚构。供应商、仓库、门店、商品名称有合理差异。覆盖多仓多店、部分发运、跨月在途、合格/不合格质检、近效期/过期、部分销售/退回、批次拆分、原料到成品转换、迟报、重复和撤销。对故意构造的质量缺陷建立机器可读清单，其他外键、单位、数量和时间逻辑须完整。

中文样例的名称、业务状态、Skill和解释用中文；英文用英文。标识、标准IRI和程序稳定代码保持一致，类型化状态代码与本地展示值分离。不要把真实GS1编号或演示编号误称为注册认证编号。
