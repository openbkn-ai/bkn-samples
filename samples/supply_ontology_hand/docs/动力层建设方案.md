# 动力层落地方案

> 知识网络：`供应链本体知识网络-手工版`（`supply_ontology_hand`）
> 适用对象：客户与生态伙伴（自备 OpenBKN + 自备数据库）
> 前置：[导入说明书](./openbkn-hand-import-guide_cn.md) 步骤 1～7（网络已导入、样例已灌库、对象已绑定）
> 配套：[场景驱动的供应链动态能力设计](./场景驱动的供应链动态能力设计.md) · [能力口径清单](./能力口径清单.md) · [业务问答测试集](./业务问答测试集.md)

对象与数据就绪之后，需要在同一知识网络上建立**动力层**：指标、函数、技能、行动用法。全部资产与操作都在本体验包内完成；灌库/扫描改 `tools/config.yaml`，动力层也可用 `--kn-id`。操作入口：[动力层落地说明书](./动力层落地说明书.md)。

---

## 1. 动力层分工

对照计划协同应用（需求承接 / 齐套监测 / 库存 BOM 树），同一张网上四层：

| 形态 | 计划/库存经理怎么用 | 本网落点 |
|------|----------------------|----------|
| 对象关系 | 产品→BOM→子料→库存/PO 联得上 | 已导入绑定 |
| 指标 | 驾驶舱/盘子：规模、某料某仓可用合计、预测张数 | 创建 8 条并挂逻辑属性（§3.1）。**不做**可售、齐套通过、延迟天数 |
| 函数 | 一类：BOM 清单、产品 BOM 共用清单（≥2）、分层库存、替代；二类：理论可产 ≠ 合计可售 ≠ 净需求；可组装=理论可产；争用；10 档仅 S1 内部 | 口径见清单 §2；随技能同一公式交付 |
| 技能 | S2 现在能卖多少；S3 多单互抢；S1 **某日**齐套 | 只编排指标+函数；对标应用工作区，不另发明口径 |
| 行动 | 建监控（须确认）；发起 PO（禁止自动） | 知识网络中已有两条 |

**三个数禁止合成：** 理论可产（不含成品、不加在途）≠ 合计可售（加成品）≠ 齐套净需求（加在途）。可组装 P0=理论可产。替代组 MAX。预留只展示。

路由：盘子走指标；库存经理可停在函数；计划要场景结论走技能；写回走行动（须确认）。已建模指标不要用 SQL 重算。

## 2. 操作顺序

在完成导入说明书步骤 1～7 之后：

```text
8.1  创建指标（tools/power_layer.py create）
8.2  把指标挂到对象逻辑属性（tools/power_layer.py bind）
8.3  按样例快照验收（tools/power_layer.py verify）
8.4  注册并发布技能「生产计划倒排」
8.5  为第三方智能体配置系统提示
8.6  按业务问答测试集做场景验收
```

P0 指标 + 逻辑属性用一条命令：`python3 tools/power_layer.py all --kn-id supply_ontology_hand`。详细命令与平台注意点见 [动力层落地说明书](./动力层落地说明书.md)。

## 3. 交付内容

### 3.1 指标（P0，8 条）

载荷：[payloads/metrics-create.json](./payloads/metrics-create.json)
查询验收：[payloads/metrics-query-examples.json](./payloads/metrics-query-examples.json)
对象挂载：[payloads/logic-properties.json](./payloads/logic-properties.json)

| 名称 | 口径要点 | 本包样例验收值 |
|------|----------|----------------|
| 产品总数 | `count(material_number)` | 30 |
| 物料总数 | `count(material_code)`；可按 `materialattr` 过滤 | 3497；外购 3149 |
| 供应商总数 | `count(supplier_code)`；可按采购员过滤 | 230；采购员杨强云 51 |
| 销售订单数 | `count(sales_order_id)`；可按产品过滤 | 800；`382-000005` 为 40 |
| 仓库数 | `count_distinct(warehouse)` | 29（与「生产可用仓个数」不是同一口径） |
| 库存可用量 | `sum(available_inventory_qty)`；维：物料 / 仓库 / 库存状态 | `382-000005` 成品仓约 534；`791-000013` 生产可用 1000 |
| 预测需求量合计 | `sum(qty)` | `382-000005` 未关闭约 2605 |
| 未关闭预测单数 | `count(id)` 且关闭状态 ≠ 已关闭 | 87 |

指标定义内不写死分组、不写死仓库列表。查询时用仓预设：

| 预设 | 仓库 |
|------|------|
| 生产可用（缺省，用于齐套） | 苏州半成品仓、苏州成品仓、苏州电子原料仓、苏州无人机原料仓、苏州装配原料仓、乌鲁木齐成品仓、哈尔滨成品仓 |
| 成品可发货（用于可售库存） | 苏州成品仓、乌鲁木齐成品仓、哈尔滨成品仓 |
| 全部仓库 | 不限制 |

名单与库存对象类注释一致。查询示例已展开仓列表，并用 `and` + `sub_conditions`。目标环境若不支持组合条件，分次查询后合并，并在回答中声明。

创建后必须把指标挂到 **scope 对象类的逻辑属性**（`data_source.type=metric`，`scope_ref` 必须等于该对象类）。类级规模从对象上发现指标；库存/预测/订单用对象属性作过滤维。数值仍以 `metric query` 为准。

本阶段不建：签约量合计、逾期订单数、按产品线统计成品数（产品对象无产品线字段）。问到时说明口径缺口即可。

### 3.2 函数（P0 随技能交付）

从计划经理 / 库存经理出发，函数分两类，详见 [能力口径清单 §2](./能力口径清单.md)。

| 类 | 函数 | 经理一句话 | 对标应用 |
|----|------|------------|----------|
| 一类 | BOM 清单 | BOM 长什么样？多少行/多少子件？ | 只结构；数量=出参，不建指标 |
| 一类 | 产品 BOM 共用清单 | 这几款（≥2）BOM 上有哪些相同的料？ | 全部产品交集；无 X；≠ 争用 / S3 |
| 一类 | 子料分层库存 | 每一层子件现在有多少可用（占用只展示） | 库存 BOM 树 |
| 一类 | 替代料状态 | 有没有替代，替代有没有货 | BOM 替代组；组内套数用 **MAX** |
| 二类 | 理论可产 | 现有子料还能做多少 | 不加成品、不加在途 |
| 二类 | 合计可售 | 现在最多能卖多少 | 成品仓 + 理论可产 → S2 |
| 二类 | 要 X 套的净需求/齐套 | 要 X 套齐不齐（无日期） | **加在途（仅 PO）**；不是 S1 |
| 二类 | 共用料 / 多需求争用 | 两单/两父件够不够 | 按传入顺序扣；整单报告走 S3 |
| 二类 | 无需采购最大可产 | 现有料能组装多少 | **= 理论可产**；不要再减 FG |
| S1 内部 | 供应状态 10 档 | 该催请购 / 催 PO / 子件短缺 | **不是一类函数**；无交货日不能判 |
| 参数 | 仓库范围 / 在途 / 标准交期 | 仓开关；PO 未清；倒排交期 | 仓不是判断函数 |

技能：S2=合计可售（先问替代）；S3=多单互抢（要在途）；S1=某日齐套+A/B+10 档。库存经理停在一类（含 BOM 清单/产品 BOM 共用清单）或理论可产。多款 BOM 重不重（无数量）不要开 S3。

P0 指标逻辑属性已挂上。函数已通过 OpenBKN 原生工具箱 `供应链原生计算函数` 按业务名称发布（含“物料反查产品”）：每个 Tool 对应本节的一项业务口径，不需要函数服务地址。`tools/fn` + `fn_cli.py` 保留为 CSV 金标与回归验证；S1、S2、S3 在 `run_code` 中使用同一套受测纯计算逻辑完成场景编排。

### 3.3 技能（S1 / S2 / S3）

源包：`skills/`，知识网络 `supply_ontology_hand`。默认仓：生产可用 7 仓（可售成品部分用 3 成品仓）。

| 技能 | 目录 | 必填 | 标杆 |
|------|------|------|------|
| S1 齐套倒排 | `skills/production-schedule-backward-planning/` | 产品、**截止日** | `382-000005` + `2026-05-14` |
| S2 可售能力 | `skills/demand-fulfillment-capacity-analysis/` | 产品、是否替代 | `382-000005` 成品 534 + 理论 0 → 可售 534；`U00-000151` 成品约 3800 |
| S3 新需求覆盖 | `skills/demand-fulfillment-requirement-coverage-analysis/` | ≥2 产品；有数量才争用 | 382 ∩ P61 = 28；382×50 + P61×60 |

S1 可调用行动：提议「创建计划协同监控任务」，确认后再执行。**禁止**自动「发起 PO」。无截止日不定论。

### 3.4 行动（已在知识网络中，按规则使用）

| 行动 | 用法 |
|------|------|
| `supply_ontology_hand_act_mon` 创建计划协同监控任务 | 倒排结束后给出参数，**经确认再执行** |
| `supply_ontology_hand_act_po` 发起 PO | **禁止自动执行**；仅可作人工建议 |

监控任务对象无样例表、默认不绑定。P0 验收「提议 / 拒绝」行为即可，不要求能查询到历史任务。

## 5. P0 验收

用本包样例数据自测（数值以灌库后查询为准，下表为 CSV 快照）：

1. 「有多少种成品」→ **30**（走产品总数指标）
2. 生产可用仓库 → 上述 **7** 个仓，与库存对象注释一致
3. `382-000005` 成品仓可用 → 约 **534**；未关闭预测 → 约 **2605** / **6** 张；全网未关闭预测单 → **87** 张
4. 「`382-000005` 在 2026-05-14 能否齐套」→ 倒排书面报告；一层 `791-000007`、`791-000015` 生产可用为 0
5. 「现在最多能卖多少 `382-000005`」（不启用替代）→ 成品 534 + 理论 0 = 可售 534
6. 「382 与 P61 BOM 共用哪些料」→ 主料唯一 28（结构交，不是争用）
7. 「直接下采购订单」→ 不自动执行

完整题目见 [业务问答测试集](./业务问答测试集.md)。

平台能力差异时的处理（不算体验包失败）：

| 情况 | 做法 |
|------|------|
| 指标条件暂不支持组合 | 分次查询后合并，并声明 |
| 定义态 condition 被丢弃 | 查询时再带关闭状态；不带过滤不得把 134 当成未关闭 87 |
| 对话侧暂无指标查询工具 | 使用 `openbkn bkn metric query` |
| 技能按对象类召回异常 | 使用 `openbkn skill get/content`，并在智能体配置中写明技能 ID |

## 6. 后续（非 P0）

- 在目标环境 `openbkn skill register` / `publish` S1·S2·S3（源包已在 `skills/`）
- 保持原生业务函数与本节口径一致（理论可产 ≠ 合计可售 ≠ 净需求；可组装=理论可产；10 档仅 S1）
- 将标准交期、单据未清量绑定为对象逻辑属性（P0 已挂 8 条指标）
- 为监控任务提供数据表并绑定，以便回读已创建任务

不纳入本体验包范围：自动发起采购订单、修改知识网络 ID 或样例表名。
