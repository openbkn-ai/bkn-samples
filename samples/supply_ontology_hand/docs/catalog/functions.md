# 函数目录

供应链样例发布相互独立的原生函数。Agent 先从业务问题选择能力，再通过 OpenBKN `tools/list` 查看所选函数的参数。函数使用 `sandbox_sdk.bkn` 在运行时读取知识网络中的所需事实；不要求 Agent 提供数据快照、认证信息或服务地址。

## 先按业务问题选择能力

| 业务问题 | 优先能力 | 不要误用为 |
|---|---|---|
| 一个产品的结构、一级主料或物料数量 | BOM清单 | 多产品争用或物料影响分析 |
| 一个物料缺货、交期变化或替代变更影响哪些产品 | 物料反查产品 | 手工遍历 BOM 父链 |
| 当前现货/可售能力是否覆盖客户数量 | 合计可售 | 制造倒排 |
| 单一产品要 X 套是否齐套、缺什么 | 要 X 套净需求与齐套 | 多产品争用 |
| 多个产品、明确数量能否同时承接 | 共用料与多需求争用 | 单产品齐套 |
| 物料的标准提前期 | 标准交期 | 产品级倒排 |
| 某日期能否交付（先判断现货，现货不足再分析生产与采购） | 生产计划齐套倒排 | 只凭内部最大延迟直接回复客户晚几天 |

交期场景先确认成品现货：若成品现货已覆盖客户数量，可直接按现货交付，不需再以制造风险否定该结论。

## 函数能力

| 函数 | 业务用途 | 业务输入与边界 |
|---|---|---|
| `bom_list` | 查看 BOM 结构 | 默认返回结构统计和一级主料；用户明确要求全量明细时才使用 `report_grain=full` 分页读取 |
| `bom_shared_list` | 查看多个产品共同物料 | 无数量时只做结构比较，不做争用结论 |
| `material_where_used` | 物料反查产品 | 输入物料编码；计数读取 `affected_product_count`；默认将替代料分支也计为潜在影响 |
| `layered_inventory` | 查看分层库存 | 占用仅展示 |
| `substitute_status` | 判断替代料状态 | 问单一物料的替代时传 `material_code`；问产品整体替代结构时传 `product` |
| `theoretical_build` | 现有物料最多能产多少 | 不含成品库存和在途 |
| `total_sellable` | 当前最多可售多少 | 成品仓 + 理论可产，不等于交期承诺 |
| `kitting_net_demand` | 要 X 套的净需求/齐套 | `gaps` 默认包含全部缺料；每项 `recommended_replenishment_qty` 是当前快照净缺，不含 MOQ/安全库存 |
| `shared_contention` | 多需求共享物料争用 | 至少两条对象需求，数组顺序就是扣减优先级 |
| `max_build_without_po` | 不新增采购最多能产多少 | 与理论可产口径一致 |
| `leadtime_days` | 标准交期 | 只读物料主数据 |
| `supply_status` | 单料供应状态诊断 | 无到位日不能判交期 |
| `open_forecast_count` | 未关闭预测单统计 | 默认返回张数与排除口径 |
| `backward_plan` | 客户履约判断与生产计划倒排 | 先返回 `fulfillment_mode`：成品现货覆盖时直接交付；否则返回客户最早物料可用日期、客户延期天数及内部 A/B 风险 |

在线调用时，函数所需数据均来自已导入、扫描并绑定的 `supply_ontology_hand` 知识网络。离线 CSV 计算仅用于本地回归验证，不是线上函数的输入。
