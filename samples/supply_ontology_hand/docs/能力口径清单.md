## 1. 指标

规则：

1. 定义内不要写死 `group_by`；切片用查询 `analysis_dimensions`
2. 定义 `condition` 只放「改了就不叫这个指标」的硬口径
3. 仓缺省用命名预设，并在结果回显
4. 禁止按 SKU/仓各建一条指标
5. **不要**把可售数量、齐套是否通过、延迟天数、满足/不满足做成指标（那是函数结果或技能结论）

## 2. 函数（计划经理 / 库存经理）

对照计划协同应用：库存 BOM 树 / 需求承接 / 齐套监测。分层见 [动态能力设计 §2](./场景驱动的供应链动态能力设计.md)。

P0 钉死：

1. **三个数分开**：理论可产 ≠ 合计可售 ≠ 齐套净需求。禁止合成「可供套数」。
2. **替代组内 MAX**（先确认启用）。对齐本包可售/覆盖技能；**不保证对齐**计划协同 UI 里替代组 SUM 后再 FLOOR 的可售数。
3. **无需采购最大可产 = 理论可产**（同一公式、同一结果）。「不含成品库存」≠ 再减一次成品仓。P0 **不做**逐层 MRP/起订量。
4. **10 档供应状态是 S1 内部判定**，不是一类函数，库存日常不要用。
5. 预留 `reserved` 只展示、P0 不减。无料号 / 无数量 X / 替代未确认 → 「不能算」。库存类函数必须回显所用仓。

### 2.1 第一类：状态查询与判断

库存经理主场。**不回答**可售、齐套是否通过、某日能不能交。

| 函数 | 谁问 | 业务意义 | 对象事实 | 开放参数 | 样例 |
|------|------|----------|----------|----------|------|
| **BOM 清单** | 这颗成品 BOM 长什么样？有多少行/多少颗子件？ | 只看结构，不带库存 | BOM 行：子件、单耗、层、是否替代 | 产品；层数（缺省一层）；是否含替代（缺省否=只主料） | 382 一层主料 **9** 颗；全树主料行 **313** / 唯一子件 **272** / 最大 **5** 层；含根总行 507 |
| **产品 BOM 共用清单** | 这几款 BOM 上有哪些相同的料？ | 结构集合交，不要数量 X | 各产品 BOM 子件码**同时出现在全部传入产品**中的交集 | **≥2** 个产品；层数；是否含替代（缺省否） | 382 ∩ P61 主料唯一 **28**；382 ∩ P61 ∩ U00-000151 **11**；**不是**争用、不是 S3 |
| **子料分层库存** | 每一层子件现在有多少？ | 库存 BOM 树 | BOM → `available`；`reserved` 仅展示 | 料号/产品；仓；层数（缺省一层） | 382 一层：`791-000013` **1000**，`007`/`015` **0** |
| **替代料状态** | 有没有替代？替代有没有货？ | BOM 替代组 | `alt_*` + 各料可用 | 料号+父件；未说启用则只报「有组未启用」 | 382 约 70 组 |

单点子料可用 = 分层库存的一行，与指标「库存可用量」同料同仓必须一致。  
**BOM 数量不是独立函数/指标**：是 BOM 清单出参（`line_count` / `unique_child_count` / `max_level` / 一层主料数）。不要按 SKU 建「BOM 行数」指标。  
产品 BOM 共用清单 ≠ 共用料争用：前者无 X、无在途，N≥2；后者要数量并判断够不够。

### 2.2 第二类：复杂判断

| 函数 | 谁问 | 怎么算（锁死） | 开放参数 | 样例 |
|------|------|----------------|----------|------|
| **理论可产** | 现有子料还能做多少？（计划/库存） | `MIN(FLOOR(生产可用/单耗))`；**不加成品、不加在途**；替代组 MAX；缺省展开到叶子主料 | 产品；仓；是否替代 | ≠ 可售 |
| **合计可售** | 现在最多能卖多少？ | `成品仓可用 + 理论可产`；成品部分用 3 成品仓 | 产品；仓；是否替代 | `U00-000151` 成品仓约 3800；`734-000001` 仅 1 |
| **要 X 套的净需求/齐套** | 要 X 套齐不齐？（无交货日） | `净需求=max(0, X×单耗 − 可用 − 在途)`；在途=未关闭 **PO** 未清；替代须已确认 | 产品/物料 + **X** + 仓 + 是否替代 | 常卡在 `791-000007`/`015`；**不是 S1** |
| **共用料 / 多需求争用** | 两单/两父件够不够？ | 共享可用+在途按**传入顺序**扣减；整单接单+报告走 S3 | `demands=[{"product":"产品编码","qty":数量}, ...]` + 是否替代 | S3：382×50 与 P61×60 |
| **无需采购最大可产** | 现有料能组装多少？（库存） | **= 理论可产**。输出不含成品库存，**不要再减 FG** | 同理论可产 | 库存经理停此，不必开 S1/S2 |

### 2.3 S1 内部：供应状态（10 档）

不是一类函数。只在 S1 已有**交货日/到位日 + 毛需求**时，对单料判定该催请购、催 PO 还是子件短缺。

无交货日 → 不能判。库存经理只问库存/替代时不要走 10 档。

在途供给量只计未关闭 PO 未清；PR 未清只用于档位（缺 PO），不计入可售/可产/净需求的供给。

### 2.4 共用口径（参数，不是判断函数）

仓范围、单据未清、标准交期是**所有相关函数的参数/分量**，不要当成又一个业务决策函数。

| 口径 | 作用 | 开放 | 注意 |
|------|------|------|------|
| **仓库范围** | 可产/齐套/净需求=生产 7 仓；可售成品部分=3 成品仓 | 预设名或仓列表 | 不得自拟昆山/新疆；须回显 |
| **在途** | 未关闭 PO 行：`max(0, 采购数量 − 实际入库)` | 单据行 | 只进净需求 / 共用料 / S3；**不进**理论可产、合计可售 |
| **PR 未清** | `数量 − 已下推`；关闭行=0 | 单据行 | 只给 S1 档位，不进供给量 |
| **标准交期** | 外购/委外=采购 LT，自制=生产 LT | 料号 | 只给 S1 倒排与 A 类延迟 |
| **BOM** | 默认只主料；损耗 P0 不计；分层库存缺省一层；可产/可售/净需求缺省到叶子 | 层数可指定 | 样例无多 BOM 版本则不选 |

### 2.5 I/O（P0）

失败：缺必填 → 返回不能算 + 缺哪项；无 BOM → 终止。数量一律向下取整。

| 函数 | 必填入参 | 出参（至少） |
|------|----------|--------------|
| BOM 清单 | 产品 | 行清单：子件、名称、单耗、层、是否替代组、父件；汇总：`line_count`、`unique_child_count`、`max_level`、一层主料数；所用口径（主料/含替代、层数）。**无库存** |
| 产品 BOM 共用清单 | **≥2** 个产品（可 3、4…） | 同时出现在**全部**传入产品中的料号；各产品上的层、单耗、父件；`shared_count`。只给 1 个产品 → 不能算。**无库存、无在途、无够不够** |
| 子料分层库存 | 产品或物料；仓范围 | 每层子料：料号、可用、占用（展示）、所用仓 |
| 替代料状态 | 产品或物料 | 是否有替代组、组数、成员可用；未确认启用则 `substitute_enabled=unknown` |
| 理论可产 | 产品；仓；`substitute_enabled` | 默认回显 `theoretical_build_qty`、瓶颈料、约束数量和所用仓；需要逐料约束时传 `report_grain=full` |
| 合计可售 | 同上 | `fg_qty`、`theoretical_build_qty`、`total_sellable_qty`；成品仓口径 + 生产仓口径分开回显 |
| 净需求/齐套 | 产品或物料；数量 X；仓；`substitute_enabled` | 默认回显是否齐套、缺料种数和缺料清单；需要逐料毛需求、可用、在途和净需求时传 `report_grain=full`；**无 A/B、无 10 档** |
| 共用料 | 各需求料号+数量（顺序=扣减顺序） | 默认回显逐单满足状态、缺料清单和扣减顺序；需要逐料分配与完整剩余池时传 `report_grain=full`；未传顺序则按数组顺序 |
| 无需采购最大可产 | 同理论可产 | 默认同理论可产摘要（可多一个 `scene=inventory_build`）；需要逐料约束时传 `report_grain=full` |
| 10 档（仅 S1） | 料号、毛需求、到位日、可用、在途、MRP/PR/PO、交期 | 档位枚举；无到位日 → `unknown` |

### 2.6 和技能怎么接

| 技能 | 对标工作区 | 调用哪些函数 | 技能多出来的 |
|------|------------|--------------|--------------|
| S2 可售 | 需求承接 · 可售能力 | **合计可售**（内含理论可产）+ **先问**替代 | 报告；**不代表交期承诺** |
| S3 新需求覆盖 | 需求承接 · 新需求满足 | 共用料 + 每单净需求 + 替代 | 业务优先级、pegging 报告；**要算在途** |
| S1 齐套倒排 | 齐套监测 + 甘特 | 分层库存 + 净需求 + 标准交期 + **10 档** +（可选）替代 | 时间窗、A/B、报告、监控/拒 PO |

库存经理：BOM 清单 / 产品 BOM 共用清单 / 分层库存 / 替代 / 理论可产 → **停在函数**。计划：先看多款共用结构→一类；现在能卖→S2；已有数量够不够→争用或 S3；某日能否交→S1。

平台在 `供应链原生计算函数` 工具箱中发布独立原生函数；Agent 通过 OpenBKN MCP 的 `tools/list` 按业务名称发现并直接调用，每个函数都有自己的用途说明和参数。函数只接收业务参数，在 OpenBKN Function Runtime 内使用 `sandbox_sdk.bkn` 读取已绑定的知识网络并完成计算；它们不读取 CSV，也不要求第三方提供数据库地址、函数服务器地址、数据快照或 Toolbox UUID。

注册或更新入口：在 `tools/` 运行 `python3 register_native_function_toolbox.py --apply`。脚本按工具箱名称解析并保留实际部署 ID；返回的 `box_id` / `tool_id` 仅用于本次环境验收。包内 `tools/fn` 与 `fn_cli.py` 仍是离线金标与回归测试工具，不是线上替代路径。S1、S2、S3 技能携带同一套受测计算逻辑，在 `run_code` 中完成场景编排。

## 3. 技能

技能只编排 §1 指标 + §2 函数 + 行动，不另发明库存/替代/齐套口径。

| 技能 | 大脑源包 | 场景 | 编排的函数 | 开放参数 | 样例 |
|------|----------|------|------------|----------|------|
| S1 齐套倒排 | `skills/production-schedule-backward-planning` | 某日能否齐套 / A/B / 10 档 | 先确认成品现货；现货不足时再用 BOM 清单 + 分层库存 + 净需求 + 交期 + **10 档（内部）** +（可选）替代 | 产品、**截止日**、数量 X、仓、是否替代 | `382-000005` + `2026-05-14`；现货已覆盖可直接交付 |
| S2 可售能力 | `src/skills/demand-fulfillment-capacity-analysis` | 现在最多能卖多少（非交期） | BOM 清单 + 替代状态 + **理论可产** + **合计可售** + 库存可用量 | 产品、是否替代料、仓 | `U00-000151` / `734-000001` |

大脑包当前是「公式写在 Skill 内」；注册到知识网络后应改为**只编排上表函数**，公式以 §2 为准。对照见 [动态能力设计 §2.4.1](./场景驱动的供应链动态能力设计.md)。

## 4. 行动

| 行动 ID | 名称 | 对象 | 智能体用法 |
|---------|------|------|------------|
| `supply_ontology_hand_act_mon` | 创建计划协同监控任务 | 监控任务 | 倒排后提议，**确认再执行**。样例无历史行 |
| `supply_ontology_hand_act_po` | 发起 PO | 从 MRP 生成采购订单 | **禁止自动**；仅人工确认后的建议 |

「发起 PO」注释：按倒排与交期，宜在交期前 2 天完成订单，以便供应商准时到货——这是业务建议时点，不是自动执行授权。

当前样例只声明这两类 Action 的业务意图，**未绑定实际 Tool**，所以在 OpenBKN 中不可执行。包内 `tools/actions/` 是可追溯的本地 `dry-run` 演示，不会创建 ERP 单据或写入客户业务系统。真实写回必须由客户在自己的环境配置审批后的业务 Tool；详见 [Action 目录](./catalog/actions.md)。
