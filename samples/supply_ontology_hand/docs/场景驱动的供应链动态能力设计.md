## 0. 定位：这不是大脑，也不是全量生产网

| 容易混淆的东西 | 本文实际钉死的 |
|----------------|----------------|
| localhost 供应链大脑 | **不作为运行面**。倒排公式、供应状态机可参考大脑实现，但智能体只消费本知识网络 |
| POC 全量网 `supplychain_hd0202`（成品 431、物料约 1.4 万、仓名「昆山/新疆」） | **不要用那套数字和仓名**。本包是脱敏子集：成品 **30**、物料 **3497**、仓名 **苏州/乌鲁木齐/哈尔滨** |
| 本包 CSV | **唯一金标准**。导入真实环境后，指标查询结果应与灌库后的表一致（允许平台聚合与 CSV 逐行加总的舍入差） |

本包业务叙事（知识网络 `comment`）：

```text
产品需求预测 → 产品 BOM → 物料需求计划 → 采购申请
 → 采购订单 → 库存齐套 → 工厂生产计划
 + 销售订单 ↔ 产品
```

组织主体在样例中为 **新疆友农科技集团**（脱敏后主体，不是原厂名）。仓库已按体验场景统一改名，库存对象类注释里写死了「生产可用仓」名单——智能体不得再发明仓列表。

## 1. 业务世界（先决策，后对象）

### 1.1 谁在问、要决定什么

本网动力层首先服务两位现场经理（销售承诺是他们的下游问法）：

| 角色 | 天天要决定的事 | 对标应用工作区 | 只查一张表做不到 |
|------|----------------|----------------|------------------|
| **生产计划经理** | 现在能卖多少；要 X 套某日齐不齐；新插两单会不会互抢 | 需求承接 + 齐套监测 | BOM + 替代 + 可用/在途 + 交期 |
| **库存经理** | BOM 长什么样、有多少子件；多款 BOM 重不重；各层有多少可用；有没有替代；现有料能组装多少（≠可售） | 库存 / BOM 树 | BOM 结构 + 库存 + 替代组 |
| 销售 / 产品经理 | 现在最多能承诺多少；新需求能不能接 | 调用计划同一套可售/覆盖 | 先问清替代料 |
| 采购员 | 请购还没转订单？订单还没到货？ | 采购跟单 | 单据未清 → **在途**（只进齐套/覆盖，不进可售） |

### 1.4 库存口径（写在库存对象注释里，属于口径不是智能体偏好）

**生产可用库存**

- 只加「可用」数量：`available_inventory_qty`
- 只加以下 **7 个仓**（样例中均有记录）：
  - 苏州半成品仓、苏州成品仓、苏州电子原料仓、苏州无人机原料仓、苏州装配原料仓
  - 乌鲁木齐成品仓、哈尔滨成品仓

**全仓可用库存**

- 仍只加 `available_inventory_qty`
- 仓库不限制（样例共 29 个仓，含借用仓、不良品仓、备件仓等）

**成品可发货库存（本设计补充的命名预设，用于可售）**

- 苏州成品仓、乌鲁木齐成品仓、哈尔滨成品仓（3 个）

缺省不问仓时：**生产齐套用生产可用 7 仓**；问「最多能卖多少」时成品库存用 3 个成品仓，理论可产仍用生产可用 7 仓。结果必须回显实际用了哪套仓。

## 2. 分层设计：对象数据 → 指标 → 函数 → 技能

对照计划协同类应用里两位经理的真实工作（需求承接、齐套监测、库存 BOM 树、采购跟单），不是「先有 API 再找场景」。

```text
计划经理「动态计划协同」          库存经理「库存 / BOM 树」
  可售（现在能承诺多少）            有效仓可用量
  新需求能不能一起接                各层子料 / 替代有没有货
  某日齐套倒排 + 监测任务           用现有料能组装多少套（≠可售）
         │                                  │
         └──────── 同一张知识网络 ──────────┘
① 对象关系   ② 指标（盘子）   ③ 函数（判断）   ④ 技能（场景）   ⑤ 行动（写回）
```

| 层 | 经理怎么用 | 不做什么 |
|----|------------|----------|
| 对象关系 | 查得到、联得上 | 不在这里发明「齐套」「可售」 |
| 指标 | 看规模和切片合计；给函数当输入 | 不把可售、齐套是否通过、延迟天数做成指标 |
| 函数 | 一颗料 / 一层 BOM / 一个数量 X 的可复用判断 | 不写交期报告；不把三种「能供几套」合成一个数 |
| 技能 | 串成业务结论 + 报告 + 治理（替代确认、禁止自动 PO） | 不另发明库存/替代/在途口径 |

**三个数必须分开**（应用里就是不同算法，合成一个函数会对不上数）：

| 业务问法 | 公式要点 | 在途 PO | 成品自身库存 | 谁用 |
|----------|----------|---------|--------------|------|
| **还能做多少（理论可产）** | `MIN(FLOOR(生产可用/单耗))` | **不算** | **不含** | 计划/库存 → 函数 |
| **现在最多能卖多少（合计可售）** | 成品仓可用 + 理论可产 | **不算** | **加上** | 计划接单前 → S2 |
| **要 X 套齐不齐（净需求）** | `max(0, X×单耗 − 可用 − 在途)` | **要算** | 在子料层扣减 | 无日期=函数；有日期 → S1 |
| **现有料能组装多少** | **= 理论可产**（P0 同一公式） | **不算** | **不含**（不要再减 FG） | 库存经理停函数 |

预留只展示、P0 不减。替代组内 **MAX**（对齐技能，不对齐 UI 的 SUM）。10 档供应状态是 **S1 内部**，不是一类函数。

确定性口径不可改写；开放料号、数量 X、仓范围、是否替代、截止日。禁止：按 SKU/仓各建指标；技能自拟仓名单或替代规则；`run_sql` 重算已建模指标；无人值守发起 PO。

### 2.1 对象 / 关系（事实层）

计划经理、库存经理先认这几条链（已在本网）：

```text
产品 ←→ BOM（多层，主料 alt_priority=0，替代组 alt_method/alt_group_no）
      → 物料 → 库存（可用 available / 占用 reserved / 仓库 / 状态）
预测 / 销售订单 → 产品
MRP → 请购 PR → 采购 PO（未清 = 在途分量）
```

仓口径写在库存对象注释：齐套用生产可用 7 仓；可发货用 3 成品仓。函数不得另发明仓名单。替代规则写在 BOM 对象注释，函数不得另发明替代组。

### 2.2 指标（盘子层）

经理用来看**网络/切片合计**，不回答「要 X 套齐不齐」：

| 经理问法 | 走指标 |
|----------|--------|
| 我们有多少成品 / 物料 / 供应商 / 订单 | 规模类 |
| 某仓、某料可用一共多少 | 库存可用量（可按料/仓过滤） |
| 预测还剩多少张、某成品预测数量 | 未关闭预测单数 / 预测需求量合计 |

指标给函数当输入（例如某料可用库存）。**不要**把可售数量、齐套是否通过、延迟天数、满足/不满足做成指标——那是函数结果或技能结论。

### 2.3 函数（判断层，两类）

完整口径见 [能力口径清单 §2](./能力口径清单.md)。

**第一类：状态查询与判断**（库存经理主场）

| 函数 | 经理问法 | 应用里对应什么 | 对象事实 |
|------|----------|----------------|----------|
| **BOM 清单** | BOM 长什么样？有多少行/多少颗子件？ | BOM 树结构（先不要库存） | BOM 行；数量=清单汇总，不单独建指标 |
| **产品 BOM 共用清单** | 这几款（≥2）BOM 上有哪些相同的料？ | 多品结构对比 | 全部传入产品的子件码交集；无 X、无在途 |
| 子料分层库存 | 每一层子件现在有多少可用？占用只展示 | 库存 BOM 树 | BOM + `available`；`reserved` 仅展示 |
| 替代料状态 | 有没有替代？替代有没有货？ | BOM 替代组 | `alt_*` + 各料可用 |

**第二类：复杂判断**

| 函数 | 经理问法 | 对齐哪条公式 |
|------|----------|--------------|
| **理论可产** | 现有子料还能做多少？ | `MIN(FLOOR(生产可用/单耗))`；不加成品、不加在途；替代 MAX |
| **合计可售** | 现在最多能卖多少？ | 成品仓可用 + 理论可产 |
| **要 X 套的净需求/齐套** | 要 X 套齐不齐？（无日期） | `max(0, X×单耗 − 可用 − 在途)`；在途=未关闭 PO |
| **共用料 / 多需求争用** | 两单/两父件够不够？ | 按传入顺序扣共享可用+在途；整单报告走 S3 |
| **无需采购最大可产** | 现有料能组装多少？ | **= 理论可产**；不要再减 FG |

**S1 内部（不是一类函数）：** 供应状态 10 档。无交货日不能判。

共用口径（参数，不是判断函数）：仓范围；在途=未关闭 PO 未清（只进净需求/S3）；标准交期只给 S1；PR 未清只进档位。

### 2.4 函数与技能的关系

技能 = 应用里的**工作区**，不是再发明一套算法。

| 技能 | 对标应用工作区 | 价值 | 调用的函数 | 技能多做的 |
|------|----------------|------|------------|------------|
| **S2 可售** | 需求承接 · 可售能力 | 接单前静态产能；**不是交期承诺** | 合计可售 + 替代（**先问**） | 报告 |
| **S3 新需求覆盖** | 需求承接 · 新需求满足 | 多单互抢 | 共用料 + 每单净需求 + 替代 | 优先级、pegging 报告 |
| **S1 齐套倒排** | 齐套监测 + 甘特 | **某日**能否齐套；A/B；建监测 | 分层库存 + 净需求 + 交期 + **10 档** +（可选）替代 | 时间窗、报告、监控/拒 PO |

```text
库存经理：BOM 清单 / 产品 BOM 共用清单 / 分层库存 / 替代 / 理论可产 → 停在函数
计划经理 · 这几款 BOM 重不重     → 一类共用清单（≥2，无数量）
计划经理 · 两边都要生产够不够   → 二类争用；整单接单 → S3
计划经理 · 现在能卖多少         → S2
计划经理 · 某日能不能交         → S1（必须有截止日/预测窗口）
驾驶舱只看盘子                   → 指标
```

无预测/无截止日：**不定齐套结论**（与齐套三步选预测单一致）。S2 可先算可售，但不得说成交期承诺。

### 2.4.1 与大脑 Skill 包对照（同一套知识，两种落地）

大脑仓库里的 Skill **已经带公式**，但是写在包内（`$kweaver-core` 取数 + `analyze`）。知识网络 Skill 应**只编排**下面这些函数/指标，公式不再另写一套。

| 大脑包（源） | KN 场景 | Skill 编排的函数 / 指标 | Skill 自己只做 | 口径注意 |
|--------------|---------|-------------------------|----------------|----------|
| `src/skills/demand-fulfillment-capacity-analysis` | **S2 可售** | BOM 清单；替代料状态；**理论可产**；**合计可售**；指标「库存可用量」（成品仓+生产仓）；仓范围 | 先问替代；一次快照；Markdown 报告；**不是交期承诺** | 可售**不加在途**（在途可进快照但不进公式）；替代组 **MAX**（与该包 `business-rules` 一致） |
| `src/skills/demand-fulfillment-requirement-coverage-analysis` | **S3 新需求覆盖** | BOM 清单；**产品 BOM 共用清单**（无数量时先摸底）；每单 **合计可售** / **净需求**；**共用料争用**；替代状态；在途=未关闭 PO | 先问替代；优先级；pegging 报告；满足/不满足 | 共享池**要在途**；结构交 ≠ 争用 |
| `skills/production-schedule-backward-planning` | **S1 齐套倒排** | BOM 清单；分层库存；净需求；标准交期；**10 档（内部）**；仓范围；指标库存/预测（对照） | 截止日；时间倒排；A/B；报告；提议监控 / 拒 PO | 无截止日不定论 |

协同规则：

1. **一个公式只在函数里钉死**；大脑包与 KN Skill 引用同一口径，禁止包内再发明可售/净需求。
2. 独立业务函数已在 OpenBKN Function Runtime 发布；大脑包和 KN Skill 保持 **I/O 字段名与函数出参对齐**（`theoretical_build_qty` / `total_sellable_qty` / `fg_qty` 等）。当前 KN Skill 在 `run_code` 内携带同一套受测纯计算逻辑，不依赖外部函数服务。
3. 库存经理只问结构/库存/可组装 → **停在函数**，不要进这三个 Skill。
4. 体验网注册时 `bkn_scope` / 默认 KN = `supply_ontology_hand`；不要写死 `supplychain_hd0202` 的仓名和 431。

### 2.5 本网已有 vs 导入后要补

| 层 | 本网 JSON 现状 | 导入真实环境后 Agent 要做的 |

## 3. 场景地图

| ID | 业务目标 | 形态 | 样例锚点（导入后应能跑） |
|----|----------|------|---------------------------|
| **S1** | 某日齐套监测（倒排 + A/B + 10 档供应状态） | 技能 | `382-000005`；承诺日 `2026-05-14` 或预测窗口；**无预测/无截止日不定论** |

### 3.1 意图路由（给智能体系统提示用）

| 用户说法 | 走哪一层 |
|----------|----------|
| 有多少成品 / 物料 / 供应商 / 订单 | **指标** 规模类 |
| 某仓某料可用一共多少 | **指标** 库存可用量 |
| 这颗成品 BOM 清单 / 有多少颗子件 | **一类函数** BOM 清单（数量是出参） |
| 这几款 BOM 上有哪些共用料（先不要数量，≥2） | **一类函数** 产品 BOM 共用清单 |
| 这颗料每一层子件库存多少；有没有替代、替代有没有货 | **一类函数**（分层库存 / 替代） |
| 要 X 套齐不齐；共用料两边生产够不够；还能供几套 | **二类函数**（复杂判断） |
| `382-000005` **5 月 14 日**能不能齐套交货 | **技能 S1**（编排一类+二类 + 时间倒排） |
| 现在最多能卖 / 能承诺多少 | **技能 S2**（先问替代；调用一类+二类，无交货日） |
| 这两单新需求能不能一起接 | **技能 S3**（二类共用料 + 每单 X 套齐套） |
| 预测还剩多少张 | **指标** 未关闭预测 |
| 帮我建个监测任务 | 提议行动 S5，确认后执行 |
| 直接给供应商下单 | **拒绝自动** |

### 3.2 标杆怎么串层（`382-000005`）

1. **对象：** 产品 → BOM 一层 9 颗主料 → 库存 / PO  
2. **指标：** 成品仓可用约 534；未关闭预测 2605（对照用，不是齐套、也不是可售结论）  
3. **一类：** 先 BOM 清单（一层 9 / 全树主料唯一 272）；若对比 P61 → 共用结构 28 颗；再分层库存 → `791-000013` 可用 1000，`007`/`015` 为 0；再问替代组  
4. **二类分开问：** 「现在能卖多少」→ 可售（534+理论可产，不加在途）；「要 X 套齐不齐」→ 净需求（可用+在途）  
5. **S2** 回答现在能承诺几套（先问替代）；**S1** 只有加上 `2026-05-14` 才回答能不能按期、A/B、10 档状态

## 4. 标杆场景 S1：生产计划倒排 · 齐套诊断

### 4.1 业务目标

计划员要一句话结论：**这个成品在这个截止日期，按当前库存、在途、计划和标准交期，能不能齐套；哪些料已经来不及下单（A），哪些是有单但交期偏晚（B）。**

### 4.2 输入（业务字段，不是界面字段）

| 字段 | 必填 | 说明 |
|------|------|------|
| 产品 | 是 | 编码或名称；样例优先 `382-000005` |
| 需求截止日 | 是 | `YYYY-MM-DD`；或可唯一解析的预测单号 / 销售承诺交期 |
| 需求数量 | 否 | 缺省：该成品未关闭预测合计，或用户指定 |
| 仓范围 | 否 | 缺省「生产可用」7 仓 |
| 报告粒度 | 否 | 摘要 / 全树 |

知识网络 ID 缺省 `supply_ontology_hand`。

### 4.3 取数（只走本网对象，一次快照）

| 用途 | 对象 | 关键字段 |
|------|------|----------|
| 锚定成品 | 产品 | `material_number` |
| 提前期、外购/自制 | 物料 | `materialattr`，`purchase_fixedleadtime`，`product_fixedleadtime` |
| 展开结构 | BOM | `bom_material_code`→成品；`parent_material_code`；`material_code`；`standard_usage`；主料 `alt_priority==0` |
| 可用 / 占用库存 | 库存 | `available_inventory_qty`，`reserved_inventory_qty`，`warehouse`，`stock_status` |
| 替代组 | BOM | `alt_method`，`alt_group_no`，`alt_priority`（0=主料） |
| 是否有净需求 | MRP | `materialplanid_number`，`closestatus_title` |
| 请购未清 | PR | `qty - joinqty`，行关闭/终止 |
| 采购未清 / 交期（在途） | PO | `qty - actqty`，`deliverdate`，行关闭/终止 |
| 可选需求窗口 | 预测 / 销售订单 | `enddate` / `promised_delivery_date`，`qty` / `signing_quantity` |

`382-000005` 样例结构要点（CSV）：

- BOM 约 507 行；一层主料 9 颗
- 一层缺口候选：`791-000007`（方向盘组件）、`791-000015`（显示终端预装）生产可用均为 **0**
- 一层充裕：`791-000013` 苏州半成品仓 **1000**；`994-000550` 生产可用 **1875**
- 成品自身：苏州成品 325 + 乌鲁木齐成品 127 + 哈尔滨成品 82 = **534**；含借用仓等全仓 **816**
- 未关闭预测合计 **2605**；全量预测 **11300**
- 销售订单 **40** 张；其中 `SO0000002` 承诺交期 **2026-05-14**

### 4.4 规则（与大脑对齐的业务算法，字段改用本网）

**倒排时间窗**

1. 成品层：`到位日 = 需求截止日`；`开工日 = 到位日 − 生产固定提前期`
2. 子件：`子件到位日 = 父件开工日 − 1 天`
3. 提前期：外购/委外用采购固定提前期；自制用生产固定提前期；空值当 0，条长再 `max(lt, 1)`
4. 若库存+在途已盖住毛需求且无未关闭 MRP 净需求，条长按 1 天（已满足，只留衔接）
5. BOM 按父→子广度优先；环路跳过；节点上限 5000

**供应状态（按顺序，命中即停）**

- 供应 = 生产可用库存 + 在途（未关闭 PO 未清量）
- 供应 ≥ 毛需求 → 充足
- 外购/委外：无 MRP → 异常（需 ERP 核查）；PO 交期已过 → 采购逾期；PO 交期晚于要求到位日 → 交期风险；无 PO 且标准交期赶不上 → 交期风险；无请购 → 缺请购；有请购无订单 → 缺采购订单；否则在途
- 自制：子件仍缺 → 子件短缺；无 MRP → 未排计划；否则计划缺口

**A / B 类延迟**

- **A 类（来不及下单）：** 外购或委外，倒排开工日已过，无采购订单，库存不够。延迟天 = 今天按标准交期到货相对要求到位日的超出
- **B 类（有单但晚）：** 有采购订单，且预计交货日晚于倒排要求到位日

### 4.5 输出与完成门槛

必须同时有：

1. 结构化结果：能否按期、最大延迟天数、A/B 清单、供应状态汇总、所用仓口径
2. 书面报告（Markdown）

未满足则**终止并说明缺什么**，禁止编造交期：

- 找不到产品
- 找不到 BOM（或展开后无子件）
- 没有截止日且无法从唯一预测/订单解析
- 库存对象查不到（绑定失败）

### 4.6 行动边界

倒排结束后：

- 可以 **提议** 创建监控任务（产品、截止日、数量、说明）→ 用户确认 → `supply_ontology_hand_act_mon`
- **不可以** 自动执行 `supply_ontology_hand_act_po`

## 5. 场景 S2 / S3（需求承接）

### 5.1 S2 可售：现在最多能卖多少

对标应用「需求承接 · 可售能力」。价值：接单前静态产能。**不是工厂交期承诺。**

```text
成品可发货库存 = Σ 成品仓 available（3 仓预设）
理论可产       = MIN( 各主料 FLOOR(生产可用仓 available / 单耗) )   // 不加在途
合计可售       = 成品可发货库存 + 理论可产
替代启用时     = 替代组内 MAX(FLOOR(成员可用/单耗))，再与主料取 MAX，各层再 MIN
```

**治理：** 未说是否用替代料 → **先问再算**。`382-000005` 约 70 个替代组。无截止日期不得说成「某天能交」（那是 S1）。

| 产品 | 成品仓可用（约） | 未关闭预测合计 | 业务直觉 |
|------|------------------|----------------|----------|
| `U00-000151` | 3800 | 4000 | 库存接近预测，可产再加一点才可能盖住 |
| `734-000001` | 1 | 20 | 不能按库存承诺 20 |
| `382-000005` | 534 | 2605 | 成品库存远小于预测；可售 ≠ 齐套 |

### 5.2 S3 新需求覆盖：多单一起能不能接

对标应用「需求承接 · 新需求满足」。价值：优先级 + **共享库存/在途池扣减**，看会不会互抢。

- 产品级：合计可售 ≥ 本单数量 → 先标满足，再按优先级扣共享池  
- 物料级可分层：半成品自身库存 → 叶子可用 → 在途 PO → 净缺口（应用 pegging L1–L5）  
- 同一 `material_code` 被 ≥2 条需求消耗 → 共用料  

数量或替代未确认 → 追问。这里**要算在途**（与 S2 可售主公式不同）。


## 7. 已知缺口（导入验证时不要误判）

| 项 | 影响 | 处理 |
|----|------|------|
| 产品对象只有编码、名称 | 不能按「产品线」过滤产品指标 | 产品线在物料 `huid_productline_name`；或列为待补属性 |
| 监控任务未绑定 | 创建前查不到历史任务 | 预期；S5 只验证「提议 + 确认后写入」 |
| PO→PR 命中率约 95% | 少数订单溯不到请购 | 报告中声明，不当成绑定失败 |
| 指标创建前 `search_schema` 无 metric | S4 问规模会失败 | 先跑 `payloads/metrics-create.json` |
| 复合条件 `and` 平台可能不支持 | 物料+仓同时过滤 | 分次查询再交，或技能内过滤 |
| 与 `supplychain_hd0202` 仓名/规模不同 | 用错金标准 | 只用本包快照 |
