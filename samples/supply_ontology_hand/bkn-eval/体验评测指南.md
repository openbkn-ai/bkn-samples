# 供应链 BKN-Eval POC 测试评估指南

本手册用于运行供应链 sample 的 BKN-Eval POC。它比较同一个智能体在两条路径上的答题质量：A 基于供应链业务知识网络答题；B 直接读取同一份样例数据答题。C 在 A、B 回答冻结后，依据答案集独立评测并给出对比结论。

本 POC 不做采购、承诺或数据写回；所有工具访问均为只读。它不是 OpenBKN 的产品功能或正式 Skill。

## 0. 运行环境就绪检查（缺一不可）

这一步是部署与运行环境的确认，不是给智能体的题目或额外任务。环境确认完成后，先让 A 执行 0.1 的准备度确认；只有通过后，才分别向 A、B、C 发送本节后的答题或评判任务提示。

| 路径 | 运行环境必须就绪 | supply-demo 的交付要求 |
|---|---|---|
| A：基于 BKN | 供应链 sample 已成功导入 OpenBKN；智能体已接入具备读取权限的 Context Loader MCP。 | sample 导入结果包括供应链知识网络、对象关系、指标、14 个具名函数和 Skill；事实查询、函数发现和函数调用均通过 MCP 完成。 |
| B：直连数据库 | 本地 `.env` 中的数据库主机、端口、数据库名、用户名和密码已准备好，并可通过只读账号连接。 | 以 [`.env.example`](.env.example) 为模板，在运行目录创建实际 `.env` 并填写连接信息。该连接必须指向 2026-08-13 的 supply-demo 快照；连通性失败时不得换用其他数据源。 |

> 不在本指南中记录地址、账号、Token 或密码明文。运行人将 [`.env.example`](.env.example) 复制为本地 `.env` 后填写；`.env` 不提交、不共享。报告只记录“连接配置版本”和快照标识，确保可复现。

已验证的运行方式是：函数只接收业务参数，在运行时自主读取已绑定的供应链知识网络；Agent 不传递 Token、服务地址、`resolved_context` 或快照载荷。localhost 已验证“生产计划齐套倒排”和“标准交期”两条真实调用。

本次评测唯一允许使用的知识网络是：**供应链本体知识网络-手工版**（ID：`supply_ontology_hand`）。环境中即使存在其他供应链知识网络，也不得自行选择或混用。

## 0.1 A 路径准备度确认（先于 50 题）

这是一段独立的环境确认提示，不计入答题成绩。运行人将它先单独交给 A；只有 A 报告“已就绪”后，才发送 A 路径任务。它只确认 MCP 的函数目录、函数执行和知识网络读取链路可用，避免 Agent 在 50 题过程中反复探测。

```text
请先完成知识网络“供应链本体知识网络-手工版”（ID：supply_ontology_hand）的 BKN 答题路径准备度确认；此时不要读取问题集、答案集、CSV、数据库连接信息、源码或其他本地文件，也不要开始答题。

1. 只使用已配置的 OpenBKN MCP；确认可发现已发布函数工具箱和函数。
2. 新建受管 Interaction，调用“标准交期”（物料 `606-000989`，预期 14 天）和“BOM清单”（产品 `382-000005`，预期 313 条明细、272 个唯一子料）。
3. 两项成功则报告“A 路径已就绪”；否则如实记录失败摘要并结束 Interaction。

不要使用 CLI、本地数据或本地计算绕过检查；不要开始答题。
```

## 0.2 三个 Agent 的独立任务提示

以下三段提示分别交给 A、B、C。不要把 A 的要求混入 B，不要把答案集提供给 A 或 B。

### A 路径任务：基于供应链知识网络答题

```text
基于知识网络“供应链本体知识网络-手工版”（ID：supply_ontology_hand）答题，只答问题集中的核心 50 题（M-01～M-15、F-01～F-15、R-01～R-09、S-01～S-11）；不答扩展题 X-01～X-08。问题集路径：<question-set-path>。不得改用或混用其他供应链知识网络。

只使用已配置的 OpenBKN Context Loader MCP。开始时通过 list_published_toolboxes、list_published_tools 按名称发现“供应链原生计算函数”及其参数；每题单独新建并结束一个受管 Interaction。

单一事实使用对象查询；简单计数、汇总使用指标；涉及 BOM 展开、齐套、可售、替代料、共同物料/争用、物料反查、交期承诺等复杂业务计算时，调用对应的已发布函数 execute_published_tool。函数仅传业务参数；不得传 Token、服务地址、resolved_context、快照或会话 ID。不得调用 CLI、run_sql 或 run_code，不得自行重建平台已有的 BOM、库存、齐套或交期逻辑。

数据基线固定为 2026-08-13；涉及“今天”、交期、延期或最早到货日时，业务日期固定为 2026-08-25。交付承诺优先使用“生产计划齐套倒排”：以 can_deliver_on_time、customer_earliest_available_date、customer_late_days 为准；max_delay_days 仅表示内部计划风险，不能直接当作客户延期。建议补货量使用“要X套净需求与齐套”的 recommended_replenishment_qty；物料反查产品数量使用 affected_product_count。题目要求完整倒排树时，使用“生产计划齐套倒排”的 report_grain=full_tree；不得用 BOM 清单节点数替代倒排树节点数。

题目明确要求完整树、完整清单或全部明细时，才传对应的完整粒度参数。函数返回的缺料清单若仅展示前 N 项，须写明“展示前 N 项，共 X 项”。函数不可用时如实记录 unavailable 与原因；可仅基于本题 MCP 已返回的数据补充计算并说明口径，但不得表述为平台函数结果。

不得读取答案集、CSV、数据库连接信息、源码、历史报告或其他本地文件；不得探测平台内部服务或网络基础设施。逐题作答，输出 Markdown 报告到会话工作区，并记录整体开始/结束时间；不要反复重试，出错或无法完成时如实记录。
```

### 手工 Skill 场景编排验证（可选扩展）

这项验证由运行人手工执行，用于确认已发布 Skill 的场景路由是否正确；它不替代 0.2 的函数基线答题，不交给 A、B、C，也不要求简单事实题使用 Skill。只抽取现有题集中的 `S-01`、`S-02`、`S-04`、`S-05`、`S-07`、`S-08`、`S-11`。

```text
仅在 A 路径准备度确认通过后，由运行人手工验证 <question-set-path> 中的 S-01、S-02、S-04、S-05、S-07、S-08、S-11。

1. 通过 OpenBKN MCP 发现并读取与当前场景匹配的已发布 Skill；不硬编码 Skill ID。
2. 依据 Skill 的业务路由，用新的受管 Interaction 做一次只读验证：事实与函数均通过 MCP 获取。
3. 每题记录命中的 Skill 名称、采用的函数、业务结论和简短路由理由。成品现货已覆盖需求时，应按现货直接交付；只有需要生产排程时才进入倒排。
4. 数据基线为 2026-08-13；交期相关结论统一以 2026-08-25 为业务日期。完成后结束 Interaction，将记录保存为手工验证报告；出错如实记录，不猜测参数格式或反复重试。
```

### B 路径任务：直连数据库答题

```text
独立完成问题集中的核心 50 题（M-01～M-15、F-01～F-15、R-01～R-09、S-01～S-11）；不答扩展题 X-01～X-08。问题集路径：<question-set-path>。可用的只读数据库连接信息位于<env-path> 。

只允许读取问题集和 .env 中的只读数据库连接信息。允许使用只读 SQL、临时脚本和计算完成作答；不得调用 OpenBKN、Context Loader MCP、指标、函数、Skill 或 Action；不得读取答案集、CSV、源码、历史报告或其他本地文件。数据库连接信息不得写入报告。

数据基线固定为 2026-08-13；涉及"今天"、交期、延期或最早到货日时，业务日期固定为 2026-08-25，不使用实际运行日期。逐题作答，输出 Markdown 报告（存放你的会话工作区）并记录整体开始/结束时间、所用计算口径。不要反复重试；出错、口径不确定或无法完成时如实记录。
```

### 评判任务：比较两份作答报告

```text
请对A（基于bkn）和B（direct-db）的答案进行评判：

A：<path-a-report>
B：<path-b-report>
答案文件：<answer-set-path>

答案准确性：先比业务结论和关键数据（数量、产品/物料编码、可交付状态、缺口、日期、是否需要澄清/拒绝）。多值答案按答案集规定的完整集合或计数判断。
硬失败：再判断是否有数据错误、未遵从业务函数/规则、遗漏必要澄清、越权执行/承诺，或证据不可回放。硬失败是正确性门禁，不代替答案比对。
效率：记录 A、B 的运行时长，并按题目类型与总体汇总比较；不引入“成本”、Token 或网络延迟指标。
仅对 A 做可解释性诊断：用答案集 basis 中的对象、关系、指标、函数、Skill、Action、顺序与证据，对照 A 的 Trace。结论应定位为数据、对象/关系路径、函数口径、Skill 编排、治理边界或回答表达的问题。

输出详细版的markdown评估报告，介绍清楚对比的背景，面向业务领导的html报告，简单扼要。
```

## 1. 运行顺序

```text
问题集 ──→ A：基于 BKN 答题 ──→ A 回答报告 ──┐
                                                   ├─→ C：对照答案集评测 ──→ 对比报告
问题集 ──→ B：直连数据答题 ──→ B 回答报告 ──┘
```

### 第一步：准备

1. 确认供应链 sample 已成功导入 OpenBKN，且 B 的只读数据库连接可用。运行 A 的 0.1 准备度确认；只有其结果为“已就绪”，才进入 A 的 50 题答题。记录 sample 版本、连接配置版本和数据快照标识，但不记录密钥。
2. 记录题集、答案集和数据快照版本；确认 A 与 B 实际读取的均为 2026-08-13 快照。
3. 将 2026-08-25 作为所有日期敏感结论的业务日期；调用支持日期参数的函数时使用其公开 schema 中的 `business_date` 参数。样例“生产计划齐套倒排”未传该参数时也默认使用 2026-08-25。
4. 为 A、B 固定相同模型参数；为每题生成唯一 `question_id`、`run_id`。
5. A 准备度通过后，分别向 A、B、C 发送 0.2 节对应的任务提示，并替换其中的实际绝对路径。A、B 可读取问题集，但不得读取答案集；C 在 A/B 报告冻结前不得读取或修改回答。

### 第二步：运行 A（基于 BKN）

1. A 读取问题集并按现有供应链 BKN 逐题作答。
2. A 应输出业务结论、必要的澄清或拒绝，以及简短依据；不要求向业务用户暴露技术字段。
3. 保存原始回答、开始/结束时间和运行状态。
4. 不允许修改已保存的原始回答。

### 第三步：运行 B（直连数据）

1. B 读取同一问题集并逐题作答。
2. B 只能读取相同快照的数据库和 `.env` 连接信息，允许 SQL/临时计算代码；不得使用 BKN 的对象关系、函数、Skill 或接口。
3. 保存原始回答、开始/结束时间、运行状态和所用计算口径。
4. 不允许修改已保存的原始回答。

### 第四步：冻结回答

确认 50 题均有 A、B 两份原始回答后，冻结两份回答报告。回答报告至少包含：`question_id`、原始问题、原始回答、开始/结束时间和运行状态；B 另记录所用计算口径。此时才将答案集交给 C。

### 第五步：运行 C（评测）

先核对两份报告是否声明数据快照 2026-08-13 与业务日期 2026-08-25；缺失时标记为“运行条件未声明”，不直接判作业务答案错误。

其余题依据答案集比较业务结论和关键数据（数量、产品/物料编码、可交付状态、缺口、日期，以及是否需要澄清或拒绝）。多值答案按答案集规定的完整集合或计数判断。

每题只判三类：`通过`、`答案不一致`、`运行条件未声明`。A/B 的工具使用差异可以作为分析背景，但不构成对答题者的额外判定要求。硬失败另列为门禁标签，说明证据和影响，但不得替代或重复计入上述答案判定。

## 4. 判定口径

| 判定 | 含义 |
|---|---|---|
| 通过 | 业务结论、关键数值与答案集一致，且运行条件已声明。 |
| 答案不一致 | 业务结论、关键数值、日期或必要澄清与答案集不一致。 |
| 运行条件未声明 | 报告缺少数据快照 2026-08-13 或业务日期 2026-08-25 的声明。 |

硬失败标签单列展示，不纳入三类答案判定的题数统计：

| 标签 | 含义 |
| --- | --- |
| 硬失败 | 存在可核验的数据错误、未遵从题目要求的业务函数/规则、遗漏必要澄清、越权执行或承诺，或证据不可回放。必须写明证据、影响和是否阻断该题结论。 |

## 5. C 的单题结果格式

每个 `question_id` 至少输出以下内容：

| 字段 | 含义 |
|---|---|
| 题目与金标结论 | 问题原文及答案集中的业务结论 |
| A 结果 / B 结果 | `通过`、`答案不一致` 或 `运行条件未声明`，并说明差异 |
| 运行信息 | A/B 的运行时长；仅陈述观测值。 |
| 结论 | 两条路径的回答差异，以及可进一步核查的业务问题。 |

## 6. 最终对比报告

报告按数据事实、函数计算、业务场景、治理边界四类题分别汇总，并给出：

1. A 与 B 的通过题数 / 总题数、答案不一致题数、运行条件未声明题数、平均和分位运行时长；
2. 两者各自答错的题号和业务原因，以及单列的硬失败标签、证据和影响；
3. 对 A 的可解释性诊断；证据不足时明确说明，不作平台故障推断；
4. 对供应链 sample 的结论：两条路径在哪些题型表现一致或存在差异，以及哪些业务问题值得进一步核查；
5. 不将单次 POC 的结果泛化为产品结论。题目、数据快照、模型或函数版本变化时，应重新运行。
