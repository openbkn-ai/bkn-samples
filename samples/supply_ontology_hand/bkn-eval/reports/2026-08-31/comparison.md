## 1. 评估背景与方法

### 1.1 背景

本评估是供应链 BKN-Eval POC 的一轮正式对比（对照《体验评测指南》，2026-08-31 轮次；此前 2026-08-30 轮次曾评估另一组报告，本报告只针对本轮两份新报告，不与旧轮次数字混算）。两条路径面对同一份问题集、同一份 2026-08-13 数据快照：

- **A 路径（BKN）**：只使用 OpenBKN Context Loader MCP，访问知识网络 `supply_ontology_hand`；主数据/单一事实用对象查询与指标，BOM 展开、齐套、可售、替代料、共同物料/争用、物料反查、交期承诺等调用已发布函数工具箱“供应链原生计算函数”（本次核验存在，含 14 个函数，与 A 报告声明一致）。每题单独新建并结束一个受管 Interaction。
- **B 路径（direct-db）**：只使用只读 PostgreSQL + 运行工作区中的临时 Python 脚本对同一快照原始表直接计算，自建 MRP 逐层净算引擎；不使用任何 BKN 接口。

### 1.2 判分规则（按任务要求）

1. **答案准确性**：先比业务结论与关键数据（数量、产品/物料编码、可交付状态、缺口、日期、是否需要澄清/拒绝）；多值答案按答案集规定的完整集合或计数判断。每题为 `通过` / `答案不一致`（含结论一致但关键数值/缺口集合不一致、以及结论相反）/ `运行条件未声明`。
2. **硬失败（正确性门禁，单独列示，不计入题数统计）**：数据错误、未遵从业务函数/规则、遗漏必要澄清、越权执行/承诺、证据不可回放——须写明证据、影响、是否阻断该题结论。
3. **效率**：只记录运行时长（分/秒），按题型与总体汇总；不引入成本、Token、网络延迟指标。
4. **可解释性诊断（仅 A）**：用答案集 `basis` 的对象/关系/指标/函数/Skill/Action/顺序/证据对照 A 的 Trace，结论定位到数据、对象/关系路径、函数口径、Skill 编排、治理边界或回答表达。

### 1.3 证据来源与限制

- A 的 Trace：A 报告逐题给出"依据"（函数/指标名 + 关键返回字段），并声明 50 个受管 Interaction 均 completed。**限制**：本会话通过平台 `list_action_executions` 查询 2026-08-31 窗口为空（该接口只覆盖行动执行，不覆盖对象查询/指标/发布函数调用），且 A 报告未附每题 Interaction ID 与完整入参/耗时 → 平台级 Trace 无法独立取回，A 证据以报告自述为准（报告级可回放）。
- B 的脚本：`kitting.py` 等留存，可重放其口径；本报告对其仓库范围、缺口口径、替代组处理做了代码级核验（见 §2.4、§3.2）。
- 环境核验（本次会话实测）：知识网络 `supply_ontology_hand` 存在；工具箱与 14 个函数名与 A 报告一致；库存对象注释明确"生产可用 = 有效仓库 7 仓（苏州半成品仓、苏州成品仓、苏州电子原料仓、苏州无人机原料仓、苏州装配原料仓、乌鲁木齐成品仓、哈尔滨成品仓）"——与金标函数口径一致，与 B 的 8/10 仓口径不同。

## 6. 结论与建议

1. **A（BKN）显著胜出**：50/50（100%）、无硬失败、11 分钟（约 13 秒/题、0.22 分钟/正确题）；B（direct-db）26/50（52%）、16 分钟（0.62 分钟/正确题），且存在硬失败（S-10 结论相反、多处口径性数据错误）。
2. **B 的失败集中在"口径复刻"**：仓库范围（8/10 仓 vs 平台 7 仓）、净需求缺口（未按金标含在途与全量净缺）、BOM 主料/去重计数、倒排节点与替代料可产等口径与金标函数系统性不一致，导致 F/R/S 系列大面积分叉，并在 S-10 给出与金标相反的供货判断（对客户有害）。B 的 M 系列 15/15 说明"直接读数"类题目两条路径均可；分歧只出现在需要"业务口径"的题目。
3. **建议以金标函数口径为统一基准**：净需求含在途、生产可用仓=平台有效仓库（7 仓）、BOM 主料去重、缺口按全量物料净缺、倒排节点按 full_tree、替代料按平台替代组语义——这些规则应固化到各路径共用的计算层，避免直连 DB 各自定义口径导致结论分叉。
4. **A 的后续优化方向（非正确性问题）**：补全 Skill 层编排（demand-fulfillment-*、production-schedule-backward-planning）并导出逐题 Trace 附件，使足迹与金标 basis 可审计对齐；当前缺口不影响答案正确性。
5. **对供应链 sample 的结论**：本体/指标/函数一层（A 路径）能把金标口径 100% 复现，直连原始表一层（B 路径）在口径未固化的前提下无法稳定复现；两者在 M 系列表现一致，在 F/R/S 系列分化明显。本轮为单次 POC，题目、快照、模型或函数版本变化时应重新运行，不将结论泛化。

## 7. 限制与可进一步核查的业务问题

- **限制**：① 平台级 Trace 本次未取回（action 执行历史为空，对象查询/指标/发布函数调用不在该接口覆盖内），A 证据以报告自述为准；② A/B 均未按题型记录耗时，分类型效率无法拆解；③ 未对数据库做逐题独立复算（B 的 24 个不一致由口径归因 + 代码核验支撑，金标以答案集 frozen 复算为准）。
- **建议核查**：① B 的仓范围口径漂移（报告 §1.2 与 `kitting.py` 不一致）——确定 B 最终采用哪套仓清单；② 金标"要X套净需求与齐套"缺口为何为 35 条（含在途）而叶子级净缺只有少量——建议将缺口定义写入函数契约文档，避免各路径自行解释；③ S-09/S-10 的能力口径（3850 vs 3920）直接影响"满足/不满足"的业务判断，建议在题集说明中明确能力=成品现货+理论可产（平台口径），并提示直连 DB 路径必须复刻该口径。
