# 2026-10-30 外部 MCP 智能体

外部智能体通过 MCP 接入 8081（bkn-backend EE 主线 9156ec5，样例 0.1.17）回答 v4 中文 50 题，可以调用样例函数。智能体是 `mcp_agent.py`：平台模型 deepseek-v4-flash（与 Studio 智能问答同一模型），加上 BKN MCP 服务提供的全部工具。系统提示只说明知识网络 ID，并要求先查技能、按技能作答。每题新开 MCP 会话；答案集不提供给智能体。逐题回答和工具调用见 `results.json`。

结果：**50/50**。这个结果不是单独一轮跑出来的，过程如下：

| 轮次 | 结果 | 处理 |
|---|---|---|
| 全量第一轮 | 自动核对 40/50 | 9 题因模型输出长度上限被截断、回答为空，1 题网关超时，都是测试工具问题。修正后（调大 `max_tokens`、令牌过期时刷新）重跑这 10 题 |
| 全量第二轮 | 47/50，人工复核 Q-49 失败 | 智能体逐个产品调用函数，超出平台单次交互的操作上限。改为“产品可做数量与可承诺量”一次接受多个产品，技能写明先用 Cypher 筛出欠货超过现货的产品，再一次传入 |
| 全量第三轮 | 47/50 | 见下表 |
| 定向补跑 | 50/50 | 只重跑 Q-18、Q-26 |

全量第三轮之后的处理：

| 题号 | 原因 | 处理 |
|---|---|---|
| Q-18 | 把“成品库存”理解成三个成品仓的库存 | 技能写明“成品库存”“现货”默认全仓，说“成品仓”时才限定三个仓，然后重跑 |
| Q-26 | 模型一次工具都没调用就回答 | 重跑 |
| Q-50 | 参考答案有误：全部催回后，上游半成品的在途也会补上，要重新逐层净扣，仍缺 8 种料而不是 10 种 | 修正 `oracle.py`，按新答案重新判分 |

Q-21 曾把可生产数量算进“现货”，第二轮前已在 PRD 和技能中写明“现货”只指成品可用库存。
