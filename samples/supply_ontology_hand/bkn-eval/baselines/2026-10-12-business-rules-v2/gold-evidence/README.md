# v3 独立金标证据

`recalculate.py` 只读交付 CSV、最终 v3 题集；不导入、不调用样例被测函数，也不读取旧答案、函数生成答案或其他 Agent 的数值。计算依据为三个业务规则 references 和题集 evaluation_policy。执行：

```sh
python3 samples/supply_ontology_hand/bkn-eval/baselines/2026-10-12-business-rules-v2/gold-evidence/recalculate.py
```

输出完整 50 题 `answer-set-v3.yaml`、逐位置 `facts.json`、输入行数与 SHA256 `provenance.json`。`expected` 是机器可读金标；`answer` 是等价 JSON 文本，`inputs` 明确仓、替代、顺序和日期条件。

库存只取 `stock_status=可用` 的 `available_inventory_qty`，不再次扣预留。每张需求先扣成品，每层库存抵扣后仅展开净缺；共享池按需求数组与原始 BOM 主料行序消耗。每位置选一种候选，比较本次父件需求可覆盖量 `min(parent_net_demand, available / candidate_usage)`，同值主料优先，再按原始行序；不混料。最终缺口只记录无子件可展开的叶子。

交付 BOM 包含替代支路的已展开子树。同层同父件多次出现会重复携带相同子件序列。脚本依据上一层父件出现次数分摊，并逐段验证候选、用量、替代组、优先级完全相同；每实际父件展开一次对应模板。证明记录在 `provenance.json.repeated_parent_validation`。结构题直接查询原始非根主料行/编码集合，不把净制造树代替结构。

容量不仅检查 N/N+1 边界，还提供独立硬上界证书：382 不替代时 528-000036 用完后，其必需叶子 165-003886 库存为零；U151 必需一级叶子 606-000065 的库存/0.1 限定129套（七仓120）；382启用替代仍受一级不可替代606-000989限定344。边界可行值等于这些硬上界，故不存在二分单调性假设留下的更高可行数量。证书与逐层扣减见 `facts.json` 对应容量题。

S08 只承认 `2026-08-25 < deliverdate <= 2026-09-08` 的有效未关闭净未收 PO；交付 CSV 中 321-000569 无任何 PO 行。库存40，不把 PR/MRP 的计划采购当供给。S06先扣足量上层588-000730组件，因此该叶子净缺为0。
