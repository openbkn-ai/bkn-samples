# 需求响应运营：业务需求文档

## 要解决的业务问题

虚构的“澄源负荷聚合”替多家企业管理空调、冷链制冷及充电设施的柔性负荷。电网侧发布响应需求后，运营团队必须回答：能承诺多少、哪些设备可以参加、多个事件争抢同一资源时怎样安排，以及响应结束后到底交付了多少、应收与客户补偿是否正确。设备额定功率、客户申报、核定基线、预测、计划、执行回执和电表读数来自不同记录，不能直接相加或混为实际交付。

这份样例的目标是支持一条可追溯的业务闭环：公告事件 → 核验客户与设备 → 评估可承诺能力 → 保留已承诺资源并提出新分配 → 核验实际执行与计量 → 对账并调查差异。场景限定为用户侧削减用电，所有数据和市场条款均虚构。

## 谁需要作什么决定

| 需求方 | 业务关切 | 需要看到的结果 |
|---|---|---|
| 聚合商运营负责人 | 当前能否接下需求，承诺后是否挤占其他事件 | 可用能力、已承诺、可新增分配、缺口及导致不确定的来源 |
| 企业能源管理员 | 削减不能破坏最低服务水平，维护或退出设备不能再入计划 | 设备资格、服务底线、场所上限、排除原因及受影响事件 |
| 响应值班人员 | 分配已经存在，但指令是否真正完成，缺少计量能否结案 | 计划与实际的区别、执行失败/缺失、计量质量及待处理证据 |
| 结算人员 | 交付门槛、应收和客户补偿是否按同一规则核算 | 核验电量、达成率、应收、补偿、净额和已入账差异 |

成功意味着这些角色能从同一份事实得到一致、带单位和来源的决策依据。数据不全时必须指出未知和责任线索；不能给一个看似精确的零或把预测当结果。

## 业务范围与观察日期

默认观察日为2027-02-28，历史事实覆盖2026年11月至2027年2月，已公告的未来响应和负荷预测延伸至2027-03-31。可以指定业务观察日和知识截止日，复现“当时知道什么”和晚到更正后的差异。中文样例使用中文企业、场所、设备及状态表达，英文样例与其业务事实、ID和数值一一对应。

所有日期到天。响应发生在有固定持续小时数的具名业务区段：peak_a为2小时、peak_b为3小时；相同日期和区段视为完全重叠。这是平均功率与区段电量的计划样例，不做秒级调控、区段内部爬坡或小时级安全认证。目标负荷预测是输入事实，不交付机器学习预测模型。

不纳入发电侧、储能SOC最优控制、潮流仿真、真实设备下发、付款执行、税费或真实电力市场规则。场所设备电表无重叠，不能再叠加场所总表制造重复电量。客户补偿与市场应收可能不同，净额可以为负。

## P0业务需求与验收场景

| 场景／需求 | 业务问题与验收条件 | 对应题目 |
|---|---|---|
| S01／R01 客户、资产与计量归属 | 找出设备所属客户/场所及唯一电表，明确设备类型和单位；不把设备铭牌功率当可承诺功率 | ENE-001—010 |
| S02／R02 预测与计划范围 | 读取截止日已知的最新预测，区分更正版本与未来目标日期；3月计划可见但不能变成实际读数 | ENE-011—020 |
| S03／R03 柔性资源准入 | 申报、服务底线、设备上限、维护、退出及有效期共同决定资格；可用零与缺少来源须区别 | ENE-021—030 |
| S04／R04 场所与计量边界 | 场所总削减不超过合同上限，设备电表不重复；聚合数可追溯至设备与场所贡献 | ENE-031—040 |
| S05／R05 多事件与已承诺资源 | 保留已承诺容量，考虑未被本次问题选中的重叠事件，任何设备或场所资源不得分配两次 | ENE-041—050 |
| S06／R06 分配与成本取舍 | 在事件优先级和既有承诺不变的前提下按增量补偿成本排序，稳定处理并列；给出缺口，不宣称全局最优 | ENE-051—060 |
| S07／R07 实际响应核验 | 只对已承诺且执行完成的资源归因，以核定基线与实际区段电量比较；明确kW与kWh转换及失败回执 | ENE-061—070 |
| S08／R08 缺失、晚到与更正 | 根据知识截止日重现当时结论；最新质量不合格不能退回旧好数据，同版本冲突必须披露 | ENE-071—080 |
| S09／R09 结算与财务差异 | 按含等号门槛判定应收，客户补偿独立计算，核验舍入与台账差异；缺台账不代表账面零 | ENE-081—090 |
| S10／R10 未来、快照与调查 | 未来事件只能评估/计划，不能报实际应收；快照与重算比较必须口径一致，异常调查返回证据和下一步 | ENE-091—100 |

每场景10题，其中简单/基础3题、中等4题、困难/复杂3题；每语共100题，30/40/30。题目需要有实质业务差异：跨事件竞争、跨知识截止日、异常传播、计量归因及财务对账，不能只替换编号凑题。

## 必须统一的业务口径

1. 功率用kW，电量用kWh，价格用CNY/kWh。先按区段小时数换算，金额按十进制四舍五入到分；未知、分母为零和真实零分别表达。
2. 可承诺能力同时受申报、设备、最低服务、预测/基线和场所上限约束。维护、退出或过期有明确原因；缺少本来可能参加的资源数据则返回不确定，不凭空判为不可行。
3. 提案不等于承诺，承诺不等于执行。重叠事件共享同一设备和场所预算；已有承诺必须保留，不能因为本次只问一个事件就忽略其他事件。
4. 交付只能从核定基线与合格实际计量得出。共享设备在多个已完成承诺间按承诺电量比例归因，合计不超过实测削减，也不超过总承诺。
5. 达成率达到约定门槛（含等号）才产生市场应收；客户已实际交付的补偿即使市场未达门槛仍发生。结果须支持零收益、负净额及未知金额。
6. 晚到与更正以可见版本处理，不使用知识截止日之后的记录。缓存指标明确其观察口径，不替代从原始事实重算。

精确公式、版本选择、输入输出和异常规则统一放在[业务计算契约](business-capability-contract.md)，避免在多份场景文档重复定义。模型映射与来源边界见[本体规范](bkn-modeling-spec.md)。

## 最小能力与交付验收

仅保留3个跨场景函数：柔性能力评估、响应分配建议、交付与结算核验；2个已记录快照指标：可用柔性能力、响应达成率；1个只读异常调查Skill。不按每道题或每种设备再增加一套函数。

本地交付必须包含中英文PRD/BKN模型、全部对象的关联样例数据、数据锁、来源和许可、可运行函数、指标定义、带实际引用文件的Skill、各100题与具体答案/证据。数据量、中文表达、日期跨度、场景覆盖和关键差异由独立子智能体核验。确定性测试通过只证明这些已知规则与数据在本地成立，不能宣称平台安装或模型问答100%准确；发布前须对固定包另作平台安装和实际问答验收，并以运行回执记录结果。
