# BKN 建模规范：金融 FIBO 样例

## 目的

本规范将已批准的业务范围和 FIBO 映射转化为原生 BKN 资源，是数据、评测和安装实现前的共同约束。

## 资源规则

1. 每张可导入表对应一个具名 BKN ObjectType。对象键使用稳定的虚构业务标识；标签字段供人阅读且可本地化。
2. P0 决策需要的跨对象业务事实对应一个具名 BKN RelationType，明确源端和目标端 ObjectType。数据中的外键字段与关系端点一一对应。
3. BKN ID 和显示名称遵守平台限制：ID 使用 ASCII 小写下划线格式，关系文件名与关系 ID 一致，任一 `id` 或 `name` 不超过 40 个字符。
4. 直接 FIBO 映射包含 `source_iri`、`source_label`、`source_definition`、`source_repository`、`source_revision` 和 `source_license`。扩展必须包含 `semantic_anchor_iri` 或书面的本地定义。
5. `as_of_date`、`effective_from_date`、`effective_to_date`、`trade_date` 和 `settlement_date` 都使用日期。任何结论都必须说明所依据日期。
6. 状态使用明确的受控值，不通过缺少记录推断。结算和估值例外必须保留原因和源记录。
7. 金额保留数值、币种、口径和截至日期。派生敞口保留构成估值 ID 和汇总规则。

## 模型层次

| 层次 | 内容 | BKN 用途 |
|---|---|---|
| FIBO 参考层 | 来源概念、定义、来源 IRI 和属性清单 | 溯源与建模指导，不是运营实例数据。 |
| 金融运营层 | 工具、实体、组合、交易、结算、持仓、价格、估值、敞口和授权对象 | 已安装的 ObjectType 和直接 RelationType。 |
| 决策层 | 限额评估和明确例外状态 | 已安装运营对象；仅在复现 P0 决策确有需要时增加指标、函数或 Skill。 |

## 禁止的捷径

- 不把匿名 OWL 限制导入为兜底实体或关系。
- 不让 FIBO 来源类看起来像真实组合、证券、法律实体或市场价格。
- 不只在 ID、自由文本说明或未经验证的计算字段中编码业务语义。
- 不为复刻一次表连接而添加指标、函数或 Skill。PRD 必须说明决策，且实现必须证明声明式 BKN 关系与文档化查询不足以完成该决策。
- 不使用真实客户、发行方、价格、交易或 LEI 数据。
