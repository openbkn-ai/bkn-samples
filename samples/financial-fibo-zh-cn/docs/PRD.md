# PRD：投资组合交易后控制样例

## 业务背景

投资管理机构的证券主数据、订单与交易、托管结算、基金会计、估值价格和风险数据通常分散在多个系统。业务人员真正关心的不是某条记录在哪个系统，而是某一持仓是否已结算、是否使用合格价格估值、是否满足投资授权，以及是否形成不可接受的交易对手风险敞口。人工跨系统拼接难以形成及时、可审计的结论。

本样例以虚构数据提供从金融工具和法律实体主数据，到成交、结算、持仓、市场价格、估值和授权限额评估的可追溯交易后控制链路。它服务于调查、数据互操作和业务演示，不执行交易、不产出官方净值，也不作投资决策。

## 业务角色与关切

| 角色 | 业务关切 | 需要的结果 |
|---|---|---|
| 投资组合经理 | 组合敞口是否符合已批准授权，哪一个持仓导致例外？ | 可追溯到工具、发行方、估值日期和适用限额的持仓级敞口。 |
| 中台负责人 | 哪些交易仍未结算或结算失败，影响哪些持仓？ | 成交至结算的证据链、明确状态和受影响持仓。 |
| 基金会计 | 一项估值能否追溯到有日期、币种和来源的价格？ | 价格来源、估值日期、数量和计算出的市值。 |
| 风险与合规负责人 | 发行方集中度或交易对手未结算卖出应收是否超过各自限额？ | 汇总敞口、限额口径、违规状态和构成记录。 |
| 数据与本体负责人 | 各系统中的金融术语是否一致、可解释？ | FIBO 语义锚点和明确的本地运营扩展。 |

## P0 决策与场景

样例必须以支持记录而不仅是布尔结果回答以下问题：

1. 在指定业务日期判断交易已结算、待结算或失败，并指出受影响持仓。
2. 用数量、金融工具、价格、价格来源、币种和估值日期解释持仓市值。
3. 找出陈旧、缺失或未批准价格的持仓，并区分价格数据例外和交易例外。
4. 按投资组合分别汇总发行方敞口与交易对手未结算卖出应收，并与各自适用的授权限额比较。
5. 将限额违规追溯到产生该敞口的持仓和交易，并在适用时显示结算例外。
6. 支持查询截至 2027 年 3 月的未来组合计划或限额生效日期，且不得把未来事实表述为当前事实。

## 业务范围

初始样例覆盖公开交易的股票和债券、带有明确本地合成标识的虚构法律实体，以及虚构市场价格。业务域包括：

- **主数据：**金融工具、标识、发行方、法律实体、币种、组合、账户、交易对手、授权限额和价格来源；
- **交易后运营：**订单、成交交易、结算指令、结算事件和结算状态；
- **持仓与估值：**持仓、带日期的市场价格、估值快照、汇率、发行方敞口、交易对手未结算卖出应收和限额评估。

业务事实使用日期字段。数据覆盖 2026 年 11 月至 2027 年 3 月；观察日为 2027-02-28：十一月至二月为实际视图，三月是从该日已知信息出发的未来计划。每项持仓、价格、敞口和限额结论都必须标明截至日期。未来限额和计划场景单独标识，不能替代已实际结算的事实。

## 成功标准

用户能够在一个连通模型中沿着“工具 → 发行方 → 成交 → 结算 → 持仓 → 价格 → 估值 → 敞口 → 限额评估”追溯。每个结论均展示日期、源记录、状态和失败原因。中英文样例具有等价事实、决策、覆盖范围和验收题。合成数据必须清晰标识，不能作为市场数据或监管申报来源。

## 边界

样例不计算监管资本、不做实时市场风险分析、不优化订单、不判定最佳执行、不替代会计总账，也不验证法律义务。衍生品生命周期、抵押品、公司行动、税务、客户适当性、反洗钱/了解你的客户筛查和官方净值核算不在范围内；这些能力需要产品特定规则、法律协议、源系统控制和治理，不能由自包含样例暗示已具备。

## 与方案设计的关系

本 PRD 定义业务结果和验收证据。BKN 模型、FIBO 映射、锁定数据、指标、函数、Skill 和安装钩子都是实现手段，不得扩大本范围。能力必须在交易、结算、价格、汇率、限额或知识截止日期变化后，仍能依据原始事实重算业务结论；只查询既有快照不能满足这一需求。


## 业务工作流与验收优先级

晨间结算排查：中台按组合和截至日期识别未结算义务，区分已逾期、未到期、部分转移与结算失败，追溯成交、指令及每笔增量转移。后续恢复或零数量确认不得重复计量。

日终账务复核：会计从期初及成交重建交易口径和已结算口径持仓，按加权平均成本解释当月与累计已实现损益。债券全价按每百元面值计量；陈旧、未批准或缺失价格不能变成零估值。只有成本可确认时允许报告成本，同时明确市值未知。

风险例外决策：风控从全组合估值计算发行方集中度；任何持仓市值未知时，禁止缩小分母后报限额内。未结算卖出应收按对手方非净额计算，不以买入抵销。选用业务日有效、知识截止日前已批准的唯一限额版本；无版本、版本重叠与实际超限分别呈现。

计划评审：组合经理比较实际与已知的2027年3月计划，明确业务日期与知识截止日期。未来已知限额只在生效后使用；不得把未来交易、价格或恢复结算当作当前实际事实。

P0 验收必须覆盖正常与异常两侧，并包含阈值相等、缺失证据、限额重叠、后知信息排除、原始数据变化导致快照失效。每个结论须有主键证据、单位/币种、日期、未知原因与可核算结果。重复模板的数量不能替代业务差异验证。

## 独立已知金额与月末核对

风险和会计必须保留可独立证明的发行方市值金额，即使其他发行方缺少合格价格。此时全组合分母及各发行方集中度比例仍未知，禁止只用有价格部分构造分母。已证明为零的金额保持零，但组合分母为零时比例仍未知。缺少期初证据绝不能补成零期初。若合格成交可唯一归属发行方但金额无法确定，仅阻断该发行方金额与全组合分母，保留其他可证明的发行方金额；若发行方无法定位，则不能证明任何发行方金额完整。

月末会计需按成交月份、本币和实际/计划视图，核对带买卖符号的已入账成交总额与剩余卖出名义金额，并仅使用知识截止已知的证据。买入总额为正，卖出为负；剩余卖出名义金额单独列示。不得把先前成交月份的未结金额带入后续月份队列，不默认本币为美元，也不混入观察时点尚未知的事实。同一成交月份队列可跨观察日期比较，用于解释转移和恢复，但队列成员不随观察日改变。

验收须区分已记录快照与重算构成。原始发行方敞口快照可因原有全组合质量策略留空，而重算发行方金额可独立已知；须分别给出范围与原因。快照为空或比例未知都不能抹去有证据的金额。验收证据应覆盖缺少期初、成交不确定性可定位及不可定位、零金额、零分母、按币种分开的队列与排除后知信息。

## 结果可信度要求

中英文事实和计算口径等价，业务表达本地化。公开题用于回归；隔离盲测用于检查未见过的问题；扰动检查数据变化后是否重算。本修订仅报告中英文公开题各100题单轮和明确授权的定向回归，不扩展重复轮次，不把未完成盲测或扰动写成通过。确定性检查的数值、完整集合、空值和证据失败不能被语言模型评分覆盖。安装、调用失败与答案错误分开报告，并保留完整分母。隔离 AI 评测不等于真人金融认证。

多观察范围请求最多20个组合、含基础范围共12个观察；单范围保留200组合输入上限。守卫按完整紧凑JSON序列化后的UTF-8字节数计量，超过3 MiB即拒绝。原生平台预检实测结果配额为4 MiB，应用的3 MiB守卫为传输保留余量。数量上限不保证任意最大输入都能成功，结果大小取决于记录和证据量。超限必须缩小组合或观察范围，绝不截断必需行或证据。原生预检及中英文各100题单轮结果见[验收报告](../../../docs/financial-fibo-183-readiness.zh-CN.md)。输入上限不代表任意输入均有运行保证；平台修复后四条指定工具路径另行通过，本修订尚未发布。
