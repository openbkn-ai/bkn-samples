# 业务场景测试集 v1

依据[业务 PRD](../../../docs/PRD.zh-CN.md)的场景和业务口径编写，共 50 题：基础 12、中等 20、复杂 18；分别从质量负责人、仓配负责人和门店店长的角度提问。题目用业务语言，不在题干里写计算规则。

- `question-set-v1.yaml`：题目、场景、难度、角色与输出要求。被测智能体只能看到这一份。
- `answer-set-v1.yaml`：机器可读的期望值。被测智能体不得读取。
- `oracle.py`：只读本包 `data/` 下的交付 CSV，库存回放、订单分配、补货和召回追溯使用评测专用的参考实现 `tools/retail_eval/oracle.py`（按 PRD 口径从原始事实计算，不导入样例函数）。中英文包使用同一份脚本，数据只在文字上不同，期望值除名称外完全一致。

```sh
python3 samples/retail-gs1-zh-cn/bkn-eval/baselines/2026-10-30-business-scenarios-v1/oracle.py
```

## 数据中的例外

业务日期有 400 个批次库位：4 个库存算不清（事件内容冲突、到货找不到发货导致负库存、负库存），157 个有隔离、189 个被召回封存、100 个已过期但还在库。4 个批次质检不合格、3 个还没检完。100 条未完成订单行按现有库存分配后，47 行全部满足、45 行部分满足、8 行一件都配不到；三月份 50 个商品仓库组合都需要补货。49 个召回进行中、REC-050 已关闭，REC-048 通过商品转换牵连到另一个商品。另有一笔重复记录的事件、一笔被冲正的销售和一笔 3 月 2 日才补录的销售。业务日期的库存和召回控制有已记录快照；其他日期、按某天已知信息、订单分配、补货和召回追溯需要按原始事件计算。
