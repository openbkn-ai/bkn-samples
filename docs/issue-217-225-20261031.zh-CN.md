## #216：公共执行器与当前样例诊断

不新增服务、日志数据库或持久化日志文件。单行 JSON 输出到服务 stderr，业务状态和 Hook 回执继续使用既有协议。

- 工作线程从持久化记录绑定 sample/version/installation/attempt/operation；重试记录前次 attempt，中断恢复保留原关联。
- 阶段状态变化输出事件；用单调时钟计时；复用已完成阶段记录跳过原因。
- 在线元数据、安装包、重定向域名、字节进度、摘要、解包和校验有诊断；离线导入和复验也有边界事件。
- 数据库准备与两个 DB Hook、发现轮询、平台 Hook、父进程 CLI、卸载平台调用与阶段清理有执行记录。
- 并发读取双流；stdout 在 16 MiB 协议上限内完整保留，超限明确失败；stderr 保留 64 KiB 尾部，失败/超时补充脱敏尾部诊断。日志单行最多 8 KiB，转发预算 256 KiB 且最多 256 条。CLI JSON stdout 不直接转储为日志。
- 保留 300 秒超时与进程组终止；采集失败也收尾进程；Python Hook 使用无缓冲输出。
- 已知令牌和数据库密码在本次安装尝试内记忆并统一去除，并处理 Bearer、敏感字段、连接 URL 和签名参数；日志不解析样例输出为可信上下文，不打印完整 argv 或环境。
- 同一异常只保留一次脱敏堆栈，日志出口或异常格式化失败不替换业务结果；失败回执不记录成执行成功。

当前 0.2.1 提供的 12 个样例已接入同一个可选诊断封装；父进程只接收白名单诊断字段，保留可信身份。逐项记录资源绑定、能力操作和验证命令，失败不再依赖只有退出码的外层 Hook。旧安装器缺少模块时按原执行路径运行；已发布旧包不重写，日志能力以包内既有脚本为准。0.2.1 明确排除的 order-basics 未改样例脚本。

阶段时间和摘要写入既有安装记录；知识网络与能力继续共用已有平台 Hook，能力耗时明确标记 shared-platform-hook，不伪称独立执行时长。完整测试与边界见 [#216 收尾记录](issue-216-diagnostics-20261031.zh-CN.md)。
