2026-10-12。使用既有 arm64 测试环境、官方主线样例服务和 Studio，未新建 OpenBKN 实例。以下结果针对含归属记录的新候选包；不改变既有正式发布包。

卸载后，按原安装记录逐个读取知识网络、数据源及工具箱/Skill，均确认不存在；对应样例数据库 StatefulSet、Service、Secret 和 PVC 清理完成。卸载供应链和世界杯期间，已安装的订单入门保持正常，系统和共享资源未清理。

安装、失败、卸载及重装记录保留；重装使用新的安装 ID。对旧安装 ID 发起卸载被拒绝，当前重装资源保持已安装。只验证实际创建的资源，不把不适用组件标记为已经导入。

## 验收中发现的问题

- 已发布 Skill/工具箱需要先调用标准状态接口下线再删除，#114 已修复并用于实际卸载。
- 世界杯三个原有标签加三个归属标签超过后端五个标签限制，#115 删除托管渲染中的冗余 `CSV` 标签；标准 BKN 校验和实际导入均通过。
- 供应链删除指标后，知识网络删除曾因后端代理同步未完成而暂时失败；稍后通过页面「继续卸载」完成。失败保留记录且禁止重装，没有跳过归属校验或把失败记作成功。
- 订单入门最初测试候选引用了错误的镜像仓库，已更正为既有正式数据镜像摘要后重新完成循环。世界杯旧失败候选也已撤回重传；失败记录保留。

旧测试资源的人工清理是用户授权的测试准备，不计入产品卸载验收；未补造归属记录。旧世界杯历史已有缺失，页面仍提示无法还原完整早期历史。

## 交付边界

本记录确认候选包的实际生命周期；正式 Release、`sample.json` / `verification.json` 及官方目录仍需按 [候选发布流程](candidate-publication.md) 经 PR 审核发布。代码或文档合并不等于目录已发布新版本。新环境在线安装的新版本还需在目录更新后验收。

卸载清除样例数据和用户修改，不做迁移、修改合并或备份。缺少归属记录的旧安装不能自动卸载。存储物理回收由 StorageClass 决定；本次不宣称真实 amd64 环境验收通过。
