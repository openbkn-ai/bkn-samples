## 实现边界

- 继续使用 stderr 单行 JSON 和既有状态文件，没有新服务、日志数据库或无限量持久化日志。
- 子进程双流并行读取，日志按原始内容预算 256 KiB 且最多 256 条；单行缓存上限 8 KiB。错误尾部有独立的小型诊断出口。
- 子进程超时、输出超限或采集异常时终止进程组并回收；日志出口或异常格式化失败不替换原业务结果。
- 已知敏感值按本次操作作用域处理，兼顾原文、多行和 JSON 转义表示；URL 去除用户信息、签名参数和片段。
- 不记录完整 argv、环境或成功的 CLI JSON 业务数据。六个供应链旧错误出口也移除了主动拼接完整命令的行为。
- 父进程对白名单子事件重新附加可信 sample/version/installation/attempt/operation；子脚本不能覆盖这些字段。子脚本阶段标为 `child_stage`，不据此修改业务安装状态。
- 知识网络导入与能力注册继续使用既有共同 Hook。能力的相关耗时明确标记 `shared-platform-hook`；实际绑定、发布和挂载用子步骤日志定位，没有新增 Hook 协议。
- 安装预检、在线元数据/说明/包下载与校验、离线导入、数据库 Hook、资源发现、平台 Hook、逐项验证、重试和卸载都有对应记录。被当前样例关闭的组件记录明确跳过原因。
- #215 的授权降级规则、#225 的平台发布校验不在本次日志修改中。
