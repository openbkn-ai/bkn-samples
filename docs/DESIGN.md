# 一键体验总体设计

## 目标与范围

客户及伙伴在自己的 OpenBKN 实例中刷新官方样例目录，查看独立版本与说明，选择样例安装并使用。作者通过标准包和固定制品发布经过验收的新版本。数据、知识网络、函数、指标、Skill 及样例接口随整个样例版本一起交付。

当前只支持官方 `openbkn-ai/bkn-samples` 源、BKN 目录或 KN JSON，以及 `openbkn.ai/sample-install.v1` 安装 profile。保留协议版本和兼容要求；第三方市场、动态插件适配器及通用迁移框架不在当前范围。

## 跨仓库职责

| 仓库 | 职责 |
| --- | --- |
| bkn-samples | 样例内容、发布协议、构建工具、固定版本及官方目录；样例服务执行安装和卸载、保存历史。 |
| bkn-studio | 首页目录刷新、离线包管理、可折叠样例卡片、版本说明、任务进度、历史及知识网络入口。 |
| bkn-foundry / bkn-sdk | 原生 BKN 规范与标准导入、查询和业务能力接口；安装器调用这些接口导入包内已有内容。 |
| openbkn-deploy | 将官方样例服务和 Chart 接入标准 OpenBKN 部署。 |

安装不调用 bkn create/creator 或生成式 Skill。样例服务部署在已有平台集群，不为每个包启动独立 OpenBKN 实例。样例数据由独立的样例 MariaDB 资源承载，与平台系统数据库分离。

## 版本与发布协议

发布协议使用 `samples.openbkn.ai/v1beta1`。`sourceId + sampleId + version` 标识一个独立版本，与 OpenBKN 平台版本分开管理。

- `catalog.json` 包含版本清单、兼容要求、说明、固定清单和验收记录引用；目录 sequence 单调递增。
- `sample.json` 声明包、数据镜像、模型格式、内容、数据绑定和体验入口；沿用原生 BKN 规范，不再定义一套业务模型。
- `package.tar.gz` 包含样例内容、安装声明、hooks 和版本说明；数据镜像单独按 digest 固定。
- `verification.json` 绑定精确包和镜像，记录实际数据库、知识网络、能力及场景验收。
- 发布元数据及说明使用完整官方提交 SHA 和 SHA-256。已发布版本不覆盖；修复或增加内容发布新版本，撤回保留历史条目。

发布顺序：内容与说明 PR → 审核后的干净提交构建固定包 → 精确包安装验收 → 发布固定 Release → 元数据 PR → 固定元数据提交的目录 PR。详见 [发布指南](candidate-publication.md)。

## 在线与离线

管理员刷新目录时，实例固定官方 main 的提交后读取目录和版本元数据，并保留最后成功缓存。普通页面读取不扫描 GitHub；目录不是实时推送。网络失败时保留已有缓存并提示失败，新环境没有远程缓存。

离线导入无需在线目录，使用完整自包含的 `offline-package.tar.gz`（offline.v2），包含数据、原生模型、声明能力及 OCI 镜像全部层。管理员先用包内工具将镜像导入每个可调度节点，随后上传包并安装。安装与重试均使用 `imagePullPolicy: Never`，不访问外部目录、注册表或镜像回退源；缺少本地制品明确失败。仅调用已安装平台和 Kubernetes 的内部接口。URL-only 旧包不视为完整离线包。参见 [完整离线安装](offline-installation.md)。

在线与离线沿用同一安装器和固定制品检查。实际安装版本与目录最新版本分开显示，不将最新目录版本伪装成已安装版本。

## 安装、进度与历史

卡片点击安装即开始任务并展示进度，进度位于版本说明上方。安装按数据库准备、资源发现、知识网络导入与绑定、能力发布、实际验证执行。检查声明的函数、指标、Skill 及业务查询；成功验收后记录安装版本。

任务保存固定版本、包／镜像摘要、资源归属和说明快照。每次接受的安装或重试保存独立 attemptId 和时间，失败也保留历史。服务状态使用 PVC、原子写入和单副本 Recreate；重启后的中断任务需要明确重试。凭据不写入任务记录。

## 卸载与版本替换

具备归属记录的安装支持卸载后重新安装。页面明确提示：卸载清除样例数据和用户对样例的修改，历史保留。

卸载依次删除知识网络及指标、函数和 Skill、数据源、样例数据库及存储，最后验证清理。按原安装记录的资源 ID、样例／版本归属和 Kubernetes UID 核对；不通过同名推断所有权。不删除平台系统数据、其他样例、共享命名空间或样例服务状态。

卸载未完成时禁止重新安装，失败可继续卸载。重装获得新的安装 ID，旧请求不能误删新资源。旧包缺少归属记录时不支持自动卸载，不能通过刷新目录补造归属。原地升级、数据迁移及用户修改合并不支持。详见 [卸载指南](sample-uninstall.md)。

## 来源与权限

官方内容经仓库 PR 审核后发布，消费者校验固定来源、摘要和兼容要求。安装、导入及删除由服务端管理员权限控制，前端按能力显示入口。加载器限制归档体积与路径，拒绝链接、特殊文件及路径穿越；不将平台认证 token 发往制品下载源。安装 hooks 使用平台标准接口，实际权限或 API 不可用时记录失败。

## 验收边界

总体进度统一见 [0.2.0 实施进度](RELEASE_0.2.0_STATUS.md)。协议和摘要校验不等同于平台安装成功；运行验收必须绑定精确样例版本和固定制品。已发布凭证保持其原有引用，历史证据可按目录固定提交读取。
