# 制造业行业样例专家评审与整改记录

评审方法参照制造业 FDE 的落地标准：先确认业务决策能否由事实复算，再审查跨系统语义、时间快照、数据守恒和验收契约。评审对象为中英文制造业样例；IOF 的 112 个参考类继续作为标准参考层，不被当作运营交易事实。

## 评审结论

样例已形成从预测、计划、供应、生产、质量、入库到发运的端到端履约链。40 个运营对象、71 条直接关系和 2,700 条记录足以演示可审计的制造履约判断。它不是 MES、APS 或供应链控制塔的替代品；有限产能、批次谱系、根因处置仍不在样例边界内。

## P0 发现与已完成整改

| 发现 | 已完成整改 | 可验证证据 |
|---|---|---|
| 库存余额不能由事务复算，短缺与发运后的余额语义不成立 | `inventory_balances` 增加 `available_quantity` 和 `as_of_date`；余额由收货、发料、成品入库和发运逐笔推导。物料短缺分支将剩余在库量完整分配，因而可用量为零。 | `tools/verify_industry_links.py` 对所有原料和成品库位复算余额。 |
| BOM、工单物料需求和计划缺少版本谱系 | 新增 `production_plans`；计划行关联计划，工单冻结 `bom_version_id`，物料需求关联 `bom_component_id`，组件关联 BOM 版本。 | 逐工单验证计划快照、产品、BOM 版本和组件物料一致。 |
| 计划状态混入事后运营状态 | 计划快照固定为 2026-10-20，覆盖 2026-11 至 2027-03；计划行仅表达已下达计划，生产、质量与发运的实际状态保留在各自事务中；库存快照明确为 2027-03-31。 | 计划与库存快照日期由验收 MFG-18 和关系校验共同验证。 |
| 仅首条链路验证发运闸门 | 对 50 条发运逐条验证订单、成品入库、最终检验、状态和数量。完成发运必须对应同工单的已接受终检和成品入库；阻塞、拒绝和待处理分支必须为零发运。 | `tools/verify_industry_links.py` 及 MFG-18。 |
| README、题库和验收仍停留在旧规模 | 统一为 40 表、71 关系、2,700 条记录和 18 个验收场景；题库 MFG-086、场景说明、能力需求和网络元数据同步更新。 | 双语 `bkn-eval/run.py` 和 `openbkn bkn validate kn`。 |

## P1 评估与当前边界

50 个业务分支满足每表至少 50 条的测试规模要求，但主数据复用和多订单资源竞争仍较弱。供应链也没有调拨、替代料或采购供给分配；质量拒绝没有返工、报废、让步接收等处置。它们会扩大为供需协同、质量处置和有限排程场景，因此不混入当前“工单与设备能力匹配、端到端履约”基础样例。

当前能力设计只保留四个可复算指标（发料覆盖率、可用库存、最终质量符合性、发运资格）、两个函数（工单履约判断、发运闸门判断）和一个分析 Skill。每一项都已有对应数据和验收依据，避免以空洞的指标或 Skill 凑功能数量。

## 验证结果

- 中英文 BKN 校验均通过：40 ObjectTypes、71 RelationTypes、3 个 ConceptGroups。
- 中英文关系与业务约束校验均通过：计划/BOM 谱系、事务库存快照和全部 50 条发运闸门。
- 中英文评估均通过：MFG-01 至 MFG-18，100 题难度结构及答案存在性校验。
- IOF 参考层校验均通过：112 个参考实例表和 7 条可直接投影的标准关系。
