# Sample 开发与版本更新指南

## 用户安装

OpenBKN 首页 → **一键体验**：刷新官方样例目录，展开卡片查看版本说明，安装后打开知识网络。管理员通过 **导入离线包** 上传自包含的 `package.tar.gz`；包内包含完整内容，安装和重试无需样例镜像或节点操作。详见 [完整离线安装](offline-installation.md)。

官方目录从 `openbkn-ai/bkn-samples` 读取，刷新成功后缓存。联网目录不是实时推送；网络失败会提示并使用已有成功缓存。新环境没有之前的目录缓存，也可导入离线包。内置样例与目录缓存是不同来源。

## 新增 sample 的在线交付完成条件

源码 PR 合并、`sample.yaml` 新增或安装器更新，都不等于在线发布。`sample.yaml` 声明包身份；仓库根目录 `catalog.json` 注册可下载的发布版本。刷新读取目录，不会把任意 Git 样例目录直接当作安装包，也不需要在 Studio 或 installer 增加名称分支。

发布完成必须逐项核对：

1. 从审核过的固定提交构建包；包内包含该 sample 的数据和 hooks，固定摘要。
2. 对精确包完成实际安装、内容及场景验收；不得复用另一个包的结果。
3. 上传精确包到不可覆盖的官方 Release 资产；提交对应 `sample.json`、`verification.json`，绑定真实验收。
4. 在 `catalog.json` 注册新身份和版本，元数据 URL 固定完整提交 SHA，递增 sequence，保留旧条目。
5. 在实例卸载 sample 并删除离线缓存包，刷新后仍能发现在线版本；由在线卡片安装、查询声明的能力、卸载并检查资源清理及历史。

只有第 5 步通过，才可记录“在线交付完成”。安装器更新不会替换缓存包；内容修订后的离线验证须删除旧缓存并导入新摘要的包。删除离线包后卡片消失，先检查是否注册在线目录以及刷新状态。

## 开发一个样例

参考最小样例 [订单入门](../samples/order-basics/README.md) 或完整 [供应链](../samples/supply_ontology_hand/README.md)。每个样例放在 `samples/<directory>/`：

| 内容 | 位置及要求 |
| --- | --- |
| 安装声明 | `sample.yaml`：身份、组件、数据模式、知识网络及安装/校验 hooks。 |
| 数据 | `data/` 和锁文件；使用虚构或脱敏数据，初始化与校验须对应。 |
| 知识网络 | `kn/`：遵循 OpenBKN BKN 规范，或使用兼容的 KN JSON；绑定当前安装生成的数据源。 |
| 函数/接口 | `tools/`：使用既有标准接口注册，验证参数、执行结果和绑定。 |
| 指标 | 既有 BKN/KN JSON 定义或样例指标资产；安装时创建、绑定，校验真实计算结果。 |
| Skill | `skills/`：内容、引用文件及依赖函数；安装、发布、挂载并验证业务场景。 |
| 版本说明 | `releases/<version>/release-notes.zh-CN.md` 或英文版本：变化、兼容性及限制。 |

仅声明实际交付的组件。安装 hooks 导入包里已有内容，不需要 creator 或生成型 Skill；不要增加样例专属的 Studio/安装服务代码。

## 修改供应链并发布新版本

1. 从主线创建分支，选择新的 sample 版本，例如 `0.1.4`。平台版本与 sample 版本独立。
2. 修改需要变化的内容，新增 `releases/0.1.4/` 版本说明。任一类内容变更，都发布整个 sample 的新版本。
3. 提交英文 PR，完成规范检查与 AI 审核后合并；从该干净提交构建最终候选。
4. 若数据变化，更新包内数据与锁文件；无需构建样例数据库镜像。
5. 构建固定包，通过首页离线入口在干净测试安装中验收所有变化，记录包摘要、共享数据库运行方式和真实结果。
6. 上传通过验收的精确包到官方 Release；提交 `sample.json`、`verification.json` 和递增 sequence 的 `catalog.json` PR。目录固定完整提交 SHA、制品 URL 和摘要；保留旧发布。
7. 审核合并后刷新实例目录，确认新版本说明，再通过正式远程入口验证安装与使用。

具体命令和发布顺序见 [候选包与正式发布](candidate-publication.md)。当前发布元数据可参考 [供应链 0.1.3](../samples/supply_ontology_hand/releases/0.1.3/sample.json)。新文件需要进入 Git 索引，否则构建工具不会打包。

### 各类更新的最低验收

- 数据：表数、锁定摘要、代表值，以及受影响的查询。
- 知识网络：对象、关系、当前数据源绑定及真实对象查询。
- 函数/接口：实际调用变化的函数，核对输入、结果及权限前提。
- 指标：按 Object Metrics V1 创建、验证并发布指定版本，检查所属对象类，实际查询与锁定数据一致。供应链的对象集聚合指标不绑定为实例逻辑属性；对应 `tools/assets/metrics-create.json`、`logic-properties.json`、`metrics-query-examples.json`。
- Skill：发布、挂载、内容与引用文件一致，引用函数可用；使用配置好的模型验证变化的场景。安装本身不要求模型，但智能问答要求模型。

包能通过 schema 或 AI 审核，不代表内容已成功导入。只保留资产文件而未注册、绑定或验证，不应记录安装成功。

内置 `v1alpha1` 样例可在 `sample.yaml` 的 `metadata.version` 声明独立样例版本。未声明的旧 manifest 保留原有 `0.1.0` 身份，不使用服务 `VERSION`；在线与离线包使用各自固定的发布版本。索引顶层版本与共享数据镜像标签仍属于服务制品版本。

## 版本边界

已经发布的同一版本不覆盖；修正内容必须新版本。目录显示新版不会自动覆盖已安装样例。不提供原地升级、数据迁移或用户修改合并。具备归属记录的新包可先卸载旧样例再安装新版本；卸载会清除旧样例数据和用户修改，保留历史。缺少归属记录的旧包不能自动卸载。实现及验收边界见 [卸载与重装](sample-uninstall.md)。

安装记录保存版本、固定内容身份、成功时间及逐次尝试，失败与后续成功都保留。历史不完整的旧记录会明确标记，不能补造。安装服务部署与持久存储配置见 [部署说明](sample-service-deployment.md)；产品部署仓库为 `openbkn-ai/openbkn-deploy`。

## 在同一环境卸载旧版本，再安装新版本

1. 按本文候选验收和 PR 流程发布新版本，不能覆盖旧包。
2. 在 Studio 已安装卡片点击「卸载样例」，确认清除样例数据及用户修改。五个清理阶段位于版本说明上方，历史安装记录保留。
3. 等待清理完成。中途失败时点击「继续卸载」，卡片回到「未安装」之前不能重新安装。
4. 在线方式刷新目录、选择新版本；离线方式删除旧缓存包后上传新固定包。删除缓存包不等于卸载平台资源。
5. 点击卡片上的「安装」，核对新安装版本，并验证数据、对象/关系及该包声明的函数、指标、Skill。历史应保留旧安装、卸载尝试及新安装。

新包须包含托管安装脚本和归属记录工具。没有归属记录的旧正式包不可覆盖，也不会仅通过更新 Studio 自动获得卸载能力。当前知识网络接口最多接受五个标签；这些托管样例使用三个归属标签，业务来源标签最多保留两个。除 BKN 语法校验外，也要核对渲染后的模型是否符合平台接口约束。

## 共享数据库补丁与离线发版

包含共享样例数据库能力的 0.2.0 补丁中，所有样例共用产品部署的样例专用 MariaDB，各自使用独立数据库和账号。`sample.yaml` 的 `spec.database` 和已有的 `dbInit`、`dbVerify` 入口继续有效；脚本通过安装器提供的 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD` 连接，不依赖本机 socket、root 账号或镜像首次启动。需要暂存库时使用当前装载脚本的 `<数据库名>_loading` 约定；不能访问其他样例数据库。

离线版本必须使用 `spec.data.mode: embedded`，包含数据、模型和声明的执行资源，不能在安装或重试时下载依赖。参见[离线交付说明](offline-installation.md)，使用 `prepare_shared_release.py` 准备同一份完整 `package.tar.gz` 及候选清单，供在线下载和离线上传。新清单声明 `database.shared` 能力，数据依赖指向 archive，不再指向数据库镜像。新增版本需要实际验收证明，不能复用旧版本的成功证明。

在 `sample.yaml` 中使用可选的 `metadata.language` 声明样例内容语言，如 `zh-CN` 或 `en-US`。新包和 Studio 目录会携带此字段，它与版本说明的语言无关。发布目录条目也可声明 `language`。缺少字段的旧包可复用目录中已声明的语言；仍无法确定时，在“全部”筛选下显示。不要为补充语言字段改写已发布的包或固定版本清单。
