# Sample 开发与版本更新指南

## 用户安装

OpenBKN 首页 → **一键体验**：刷新官方样例目录，展开卡片查看版本说明，安装后打开知识网络。管理员可通过 **导入离线包** 上传 `package.tar.gz`；数据镜像需要目标集群可访问或事先准备。

官方目录从 `openbkn-ai/bkn-samples` 读取，刷新成功后缓存。联网目录不是实时推送；网络失败会提示并使用已有成功缓存。新环境没有之前的目录缓存，也可导入离线包。内置样例与目录缓存是不同来源。

## 开发一个样例

参考最小样例 [订单入门](../samples/order-basics/README.md) 或完整 [供应链](../samples/supply_ontology_hand/README.md)。每个样例放在 `samples/<directory>/`：

| 内容 | 位置及要求 |
| --- | --- |
| 安装声明 | `sample.yaml`：身份、组件、数据模式、知识网络及安装/校验 hooks。 |
| 数据 | `data/` 和锁文件；使用虚构或脱敏数据，初始化与校验须对应。 |
| 知识网络 | `kn/`：遵循 OpenBKN BKN 规范，或使用兼容的 KN JSON；绑定当前安装生成的数据源。 |
| 函数/接口 | `tools/`：使用既有标准接口注册，验证参数、执行结果和绑定。 |
| 指标 | 既有 BKN/KN JSON 定义或样例指标资产；安装时创建、绑定，校验真实计算结果。 |
| Skill | `skills/`：内容、引用文件及依赖函数；安装、发布、挂载并验证业务场景。 |
| 版本说明 | `releases/<version>/release-notes.zh-CN.md` 或英文版本：变化、兼容性及限制。 |

仅声明实际交付的组件。安装 hooks 导入包里已有内容，不需要 creator 或生成型 Skill；不要增加样例专属的 Studio/安装服务代码。

## 修改供应链并发布新版本

1. 从主线创建分支，选择新的 sample 版本，例如 `0.1.4`。平台版本与 sample 版本独立。
2. 修改需要变化的内容，新增 `releases/0.1.4/` 版本说明。任一类内容变更，都发布整个 sample 的新版本。
3. 提交英文 PR，完成规范检查与 AI 审核后合并；从该干净提交构建最终候选。
4. 若数据变化，更新锁文件，发布包含新数据及 hooks 的数据镜像并固定 digest。数据不变可复用已验证镜像。
5. 构建固定包，通过首页离线入口在干净测试安装中验收所有变化，记录包摘要、数据镜像和真实结果。
6. 上传通过验收的精确包到官方 Release；提交 `sample.json`、`verification.json` 和递增 sequence 的 `catalog.json` PR。目录固定完整提交 SHA、制品 URL 和摘要；保留旧发布。
7. 审核合并后刷新实例目录，确认新版本说明，再通过正式远程入口验证安装与使用。

具体命令和发布顺序见 [候选包与正式发布](candidate-publication.md)。当前发布元数据可参考 [供应链 0.1.3](../samples/supply_ontology_hand/releases/0.1.3/sample.json)。新文件需要进入 Git 索引，否则构建工具不会打包。

### 各类更新的最低验收

- 数据：表数、锁定摘要、代表值，以及受影响的查询。
- 知识网络：对象、关系、当前数据源绑定及真实对象查询。
- 函数/接口：实际调用变化的函数，核对输入、结果及权限前提。
- 指标：定义与逻辑属性绑定，实际查询与锁定数据一致。供应链对应 `tools/assets/metrics-create.json`、`logic-properties.json`、`metrics-query-examples.json`。
- Skill：发布、挂载、内容与引用文件一致，引用函数可用；使用配置好的模型验证变化的场景。安装本身不要求模型，但智能问答要求模型。

包能通过 schema 或 AI 审核，不代表内容已成功导入。只保留资产文件而未注册、绑定或验证，不应记录安装成功。

内置 `v1alpha1` 样例可在 `sample.yaml` 的 `metadata.version` 声明独立样例版本。未声明的旧 manifest 保留原有 `0.1.0` 身份，不使用服务 `VERSION`；在线与离线包使用各自固定的发布版本。索引顶层版本与共享数据镜像标签仍属于服务制品版本。

## 版本边界

已经发布的同一版本不覆盖；修正内容必须新版本。目录显示新版不会自动覆盖已安装样例。不提供原地升级、数据迁移或用户修改合并。具备归属记录的新包可先卸载旧样例再安装新版本；卸载会清除旧样例数据和用户修改，保留历史。缺少归属记录的旧包不能自动卸载。实现及验收边界见 [卸载与重装](sample-uninstall.md)。

安装记录保存版本、固定内容身份、成功时间及逐次尝试，失败与后续成功都保留。历史不完整的旧记录会明确标记，不能补造。安装服务部署与持久存储配置见 [部署说明](sample-service-deployment.md)；产品部署仓库为 `openbkn-ai/openbkn-deploy`。
