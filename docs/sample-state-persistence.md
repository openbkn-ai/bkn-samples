# 样例服务状态持久化

当前为本地候选实现，已部署到用户指定的 kind-bkn-dev；PVC 已绑定、服务已启动，Pod 重建验收尚未运行。

## 最小部署约束

安装器沿用文件状态和进程内锁，首期只支持单副本。Chart 拒绝 replicaCount 不为 1，Deployment 使用 Recreate，避免正常滚动更新期间新旧 Pod 同时写状态。更新期间会有短暂服务中断；强制删除 Pod、网络分区和多个独立部署不能依靠它实现分布式互斥。

状态卷默认创建 ReadWriteOnce PVC，挂到 `/var/lib/bkn-samples`，保存当前安装记录、说明快照和官方目录缓存。PVC 设置 Helm keep，卸载不自动删除记录。容量默认 1Gi，storageClass 留空使用集群默认类；没有默认类时必须配置。也可指定同命名空间的已有 PVC：

```yaml
persistence:
  existingClaim: ""
  storageClass: ""
  size: 1Gi
```

existingClaim 非空时 Chart 不创建 PVC；管理员需确认它的容量、访问模式、归属和备份。keep 不替代备份，也不能保证删除集群后保留数据。重新安装采用原保留卷时，显式填写 existingClaim，避免依赖 Helm 自动接管历史资源。

## 文件写入

安装记录和目录缓存使用统一原子写入：在目标目录生成权限 0600 的临时文件，完成文件 flush/fsync，原子替换目标文件，再同步目录。状态目录权限为 0700。读取者看到上一个完整快照或新快照，不应读取到半份 JSON。存储后端须支持这些文件系统语义；底层介质损坏和不可靠持久化仍需备份处理。

供应链 hook 配置含样例数据库凭据，目录限制为 0700，不返回到 Studio；用户 Bearer token 只传给本次进程，不写入安装记录。归档和镜像构建排除本地配置、密钥文件与缓存，PR 仍需审核实际源内容。

原子文件写入没有实现多进程事务、完整安装历史或重启后的自动恢复。已完成安装的版本、时间和说明可以读取；服务启动时将遗留 installing 标记为 failed / install_interrupted，保留阶段、版本、摘要与资源引用，允许管理员按原任务重试，不自动重放安装，不清空记录重新安装。

## 旧 emptyDir 迁移

1. 更新前保存当前状态目录到受保护的备份位置；备份可能含样例数据库配置，不能提交或输出到日志。
2. 停止新安装，确认在途任务是否完成；记录真实平台资源与归属。
3. 创建或指定 PVC，把状态导入卷中，再使用单副本新部署挂载。不能直接把 Helm 升级当作自动复制 emptyDir 内容。
4. 核对成功安装版本、说明、资源入口及目录缓存，再重建 Pod 确认记录保留。
5. 回退仍需挂载原 PVC；回退到旧 emptyDir 模板会再次隐藏状态，不能据此把已有资源判断为未安装。

此前已丢失的记录不能从目录版本推算。应先核对平台资源，标记待确认，不能伪造安装时间或完整历史。

## 本地实例前提

2026-10-09 只读盘点确认：localhost:8081 对应 kind-bkn-dev，已有默认 standard 存储类。OpenBKN 位于 openbkn 命名空间，样例服务未部署，没有对应 Service、Ingress 或状态 PVC。因此当前无样例服务 emptyDir 可迁移；首次部署可直接使用 PVC。样例数据库另建在 openbkn-samples，不能覆盖 resource 命名空间已有 MariaDB。

用户确认宿主为 macOS、M5。候选容器按 linux/arm64 构建；macOS 本地 CLI 只用于连接管理，不把其可执行文件复制到 Linux 镜像。

本地候选已配置平台入口及跨命名空间 bkn-safe 地址，并固定服务镜像与数据镜像。首次部署成功，状态 PVC 为 Bound，Pod 为 1/1 Running；只读清单接口可用。Pod 重建后的记录保留、在途恢复和实际安装尚未验收，不能由启动成功推断。
