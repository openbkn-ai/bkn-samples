### 版本更新与升级的明确边界

首期完成的是“修改内容 → 发布独立新版本 → 实例扫描 → 选择未安装版本并首次安装”。PR 校验结构/来源/不可改写，真实平台验收检查内容及能力可用；两者共同作为目录发布门槛。指标遵循现有 BKN/KN JSON 内容规范，不新增指标协议。

已安装同一 sample 的原地升级、数据迁移、用户修改合并、能力替换及升级失败回退继续延后。新版出现不能开放一个语义不完整的覆盖安装按钮。后续确有升级需求时再独立确定资源迁移和保护规则。

完整安装历史是首期目标，现有单条记录只是过渡实现；需在 N6 补齐，不能因升级延后而一并取消。
