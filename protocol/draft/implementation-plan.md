## 需要在批次 2 决定的内容

1. 固定模型规范、解析器与 SDK revision，以及实际平台支持范围。现有 SDK 默认版本不是部署版本证据。
2. 一个固定安装 profile、BKN/KN JSON 的支持范围与现有数据库绑定规则。
3. 安装 API、操作者身份、权限与凭据交付、任务持久化和恢复职责。
4. 成功版本、release notes 快照、分页安装历史、冲突与重试语义。

## 验收要求

作者结构校验、模型校验、完整制品核对和真实平台验收分别提供证据。PR 的 AI 批准不能替代平台验收；发布流水线必须消费验收过的固定摘要。协议示例的假制品不进入正式目录。

旧 `samples.openbkn.ai/v1alpha1` 和现有安装链路的迁移单独实施。本批只提供独立发布草案与作者工具；不能将 `v1beta1` 示例交给现有运行时安装。

## Studio 交互补充

首页采用可展开、收起的现有卡片，默认全部收起、一次展开一张；收起不影响任务，避免增加页面或向导。U0 先实现卡片展开收起，并整理现有 DTO 的 installedVersion、每卡版本、错误归属和状态反馈；U1 对接远程目录与指定版本说明；U2 对接异步安装与历史。有新版本只展示说明，升级与卸载延后。

完整交互依据在 bkn-studio 的 `docs/plans/2026-10-09-sample-experience-interaction-design.md`。当前 Studio 已通过 `/studio/samples` 获取列表，远程 GitHub 扫描仍需安装服务实现；普通 GET 重新加载不等于扫描发布源。

本地过渡接入：现有 v1alpha1 内置版本增加说明查询、现有单条安装记录查询、成功时间、说明快照，以及版本/清单摘要提交核对。说明添加到索引构建，Studio 卡片展开区消费这些接口。范围及限制见 [兼容接口说明](../../docs/studio-version-api.md)。未完成多版本、完整历史、异步任务或远程扫描；尚未提交及运行验证。

后续发现实现已在本地写入：官方 main 提交固定扫描、原子缓存、刷新反馈、远程版本聚合与说明摘要核对，Studio 支持浏览版本切换。详见 [官方目录发现](../../docs/official-catalog-discovery.md)。当前官方根目录文件尚未发布，未执行真实扫描联调；远程版本安装仍不可用。下一批为真实候选制品和验收，之后才能正式发布并接动态安装。
